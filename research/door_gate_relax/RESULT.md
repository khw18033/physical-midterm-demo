## 핵심 관찰
- 현재 GroundingDINO 규칙(부분일치 "door pedestal"도 door, 0.15)에서는 색 1등 조건이 rot8 오탐을 혼자 막고 있어,
  게이트 기준만 풀면 rot8이 깨진다(K1). door 전용 GDINO 필터가 기준 완화의 전제다.
- 전역 GDINO box 0.25는 rot8 135° 단상(GDINO 0.17~0.24)을 없앤다 → 반드시 door에만.
- 색 순위(top-k) 완화는 무의미: 8색 유사도가 0.01 안에 몰려 조명 따라 로봇 문이 6등까지 떨어짐. 차이(tol)로 풀어야 함.
- 참조이미지·모양 게이트는 실제 문(0.745~0.809 / +0.0001~+0.0059)과 오탐(최대 0.83 / +0.021)이 겹쳐 변별력 없음.
- YOLO-World는 문 점수가 0.002~0.004(오탐 0.03)라 door에 기여 없음. conf를 낮추면 오탐만 는다 → 0.05 유지.
- 종횡비 1.3 이하는 박스가 옆 물체까지 부풀어(21→29px) 문 크기 기반 거리 추정을 흔든다 → 1.5 유지.

## 반영 후 검증(운영 코드, 패치 없음)
1. `verify_e2e.py prod`: rot8/robot 16장 결과가 K4 런타임 패치 검증(`e2e/summary_K4.json`)과 박스까지 동일. 단상 90°/135° 유지.
2. `aug_e2e.py`: 변형 22세트(무손실 PNG 입력)에서 문 34/44·오탐 2, 오프라인 재현과 세트별 불일치 0건.
   rot8은 22세트 전부 113/132만. robot은 감마 밝게·대비 저하·채도 저하·따뜻한 색온도에서 문 0(채도 63~73 / 색 차이 -0.012~-0.015 / sim 0.242~0.249).
3. `pipeline_run.py before|after` + `pipeline_diff.py`(탐지→위치 추정→경로 전체):
   - rot8: 단상 기반 위치 추정 그대로, 회전 -74.6° -> -74.7°(315° 문 박스 미세 변화), 전진 6.336m 동일.
   - robot: 225° 문이 새로 잡혀 문만으로 위치 추정(B)이 바뀜 — 문 거리 686.5 -> 648.9cm, 문 방위 265.6° -> 257.1°,
     로봇 명령 -94.4°/6.065m -> -102.9°/5.689m. 원인은 탐지가 아니라 경로 계산: 같은 문을 화면 끝(225°, 오프셋 23.65°)과
     중앙 근처(270°, -4.4°)에서 본 보정 방위가 17° 어긋나고(끝 쪽이 과소 — rot8에서도 끝 쪽 관측이 10.4° 어긋남),
     225° 박스가 옆 장까지 합쳐져(폭 32.6px, 정답 27px) 폭 기반 거리가 439.7cm로 튄다. 둘 다 단순 평균/중앙값에 들어간다.
4. `detect_api_server.py --run-dir pipeline/after/robot`: 응답 정상. mandatory_gates는 넷(참조이미지 없음)에
   target_color_gap/positive_minus_negative/tolerance가 추가됨. 225° 근거는 winning_color=white(차이 -0.0109, 허용 0.012로 통과) --
   관제 웹 gateWords는 "✓ 색 white"로 보인다.

# viz-debugger

**통합 가시화 앱.** 화면은 **노드 캔버스 하나**다 — 임무의 실행 노드와, 거기에 연결해 값을 보는 **뷰 노드** 넷(`web-dashboard`에서 이식해 온 화면들).

```bash
npm install
npm run dev
```

`npm run dev` 하나로 **목 게이트웨이(8790) · 화면(5174) · STT 서비스(8801) · 생성 서비스(8802)** 가 함께 뜬다(뒤의 둘은 파이썬 환경이 있을 때만 — 절차는 저장소 루트 [README](../README.md)). 기존 대시보드(5173/8787~8788)나 `stt-lab`(8799)과 포트가 겹치지 않으므로 **동시에 띄워 비교**할 수 있다.

```
마일스톤 목록
└ 노드 캔버스
   ├ 팔레트 ─────── [장치·위험] [제어] [지표] [영상]      VZ-N-01
   ├ 실행 노드 ──── 태스크 그래프 (DAG · 밴드 접기 · 잰 폭/높이에 맞춰)
   ├ 뷰 노드 ────── 팔레트에서 꺼내 태스크에 잇는다        VZ-N-02
   └ 확대 보기 ──── 오버레이. 캔버스를 교체하지 않는다      VZ-N-05
```

> **탭 다섯은 2026-09-03에 없어졌다** (노드 통합 3단계). 탭②~⑤의 요구 7건은 뷰 노드로
> **자리만 옮겼고 하나도 죽지 않았다** — 요구사항 45 → 50건(신설 `VZ-N-01`~`05`, 삭제 0건).
> 탭 다섯이 살아 있는 마지막 지점은 태그 `5tab-baseline` 이고, 그것이 논문 §3-2 요인 B의
> **대조군 빌드**다. 탭⑥(파이프라인 편집기)은 그보다 앞선 2026-08-31에 제거했다.

**`web-dashboard`를 대체하지 않는다.** 그쪽은 한 줄도 고치지 않은 **기준선**으로 계속 산다 — 문제가 생겼을 때 "내가 깼는지 원래 그랬는지"를 가르는 유일한 기준이다. 게이트웨이와 데이터는 목이며 화면 상단에도 그 사실을 표시한다.

## 노드 캔버스 — 임무 설계 및 디버깅

마일스톤과 노드를 클릭해 다음 계층으로 이동하고, **머리줄의 이동 경로**(`마일스톤 › MS-… › T-…`)로 되돌아온다 — 맨 앞 칸이 마일스톤 목록이다 (2026-09-01). 마일스톤 카드 배정, 그래프 노드 자유 배치, `[이 마일스톤][임무 전체]` 범위 전환, 노드 더블클릭, **하드웨어 카드 더블클릭 → 대상 상태**, 임무 이력 리플레이, 실패 파라미터 수정이 동작한다. 그래프는 **자리 폭과 높이를 재서 밴드로 접는다** — 「임무 전체」도 첫 화면에 다 들어오고, 남는 세로를 놀리지 않는다 *(2026-09-04)*. 배치 모드 토글(DAG/트리)은 없어졌다 — 회의록 §10 미결이 **그래프로** 닫혔고(요구사항정의서 §7.10), 트리 비교는 `npm run measure:representation` 과 논문에서만 다룬다. 상단 바의 **`⇄ 연결 관리`** 로 접속 주소를 화면에서 정한다 (`VZ-C-07`). 계획 승인·거부(`VZ-U-07`)는 **마일스톤 목록 위 제안 카드**에 있고, 결정이 끝나면 `✓ 승인됨 · 시각 · plan_id · [근거 ▾]` 한 줄로 접힌다. 정적 전달본과 논의 항목은 [HANDOFF.md](./HANDOFF.md)에 정리했다.

**뷰 노드**는 팔레트에서 꺼내 태스크에 연결한다 — **연결이 곧 범위**다(`VZ-N-02`). 그 태스크의 대상 장비·실행 구간이 그대로 그 노드의 조회 범위가 되고, 연결하지 않은 **전역 노드**도 허용한다(둘은 연결선 유무로 구별된다). 접힌 카드는 「확대하지 않고도 이상함을 알아챌 수 있는 값」을 담고, **더블클릭하면 그 자리에서 확대**된다 — 캔버스는 뒤에 그대로 있고 닫으면 정확히 같은 자리다(`VZ-N-05`). 캔버스 구성은 **마일스톤별로 저장**되어 새로고침에도 살아남는다(`VZ-N-04`).

**캔버스만 담는 단독 빌드가 따로 있다** (`npm run build:standalone`). 논문 측정축 D(계측 오버헤드)를 잴 때 이식 화면들의 부하가 섞이면 안 되기 때문이고, `verify:standalone`이 그 격리를 강제한다 — 뷰 노드의 **실물은 통합 빌드가 주입**하고(`integrated.tsx` → `registerViewNodes`) 단독 빌드는 주입하지 않아 팔레트 자체가 뜨지 않는다.

## 뷰 노드 넷 — 이식본

`web-dashboard/src/{data,views}` 를 `src/tabs/` 로 옮긴 것이다. **거의 무수정**이고 고친 곳은 이식 보고서(`reports/2026-08-28_1900_탭이식.md`)에 있다. 폴더 이름 `tabs/` 는 이제 「탭이었던 화면들」이 아니라 **「단독 빌드에 들어가면 안 되는 것들」**이라는 뜻이다.

| 뷰 노드 | 접힘 = 요약 카드 | 확대 |
|---|---|---|
| 장치 · 위험 | 4종 판정 + 배터리 + 상태 3층 + 위험도 등급 | `RiskPanel` · `ZoneMapMini` · `DeviceGrid` |
| 제어 | 명령 수 + 마지막 명령의 4단계 위치 | `ControlPanel`(감사 이력 포함) |
| 지표 | 미니 스파크라인 + 요약/원본 표기 | `MetricsView` |
| 영상 | 대표 **정지 프레임** + 탐지 수 + 프레임 참조 유무 | `VideoOverlayView`(재생) |

- **명령 출구는 하나다.** 제어 노드의 수동 제어도 캔버스의 재실행도 `shared/commandCenter.ts`를 거친다. 4단계 추적(발행→ACK→진행→완료)과 감사 필드가 그 안에 있다.
- **목 게이트웨이도 하나다.** `web-dashboard/mock-gateway/`가 본체가 되고, 옛 10줄짜리 시나리오 재생기가 그 안의 `trace_event` 채널로 접혔다.
- **`registry.json`은 복사하지 않는다.** `web-dashboard/mock-gateway/registry.json`을 경로로 참조한다 — `stt/vocab.py`도 같은 파일을 읽으므로(`REQ-305`) 두 벌이 되면 화면의 장치 목록과 음성 어휘가 갈라진다.

## 음성 인식 (`VZ-L-01`)

발화 패널의 녹음·인식은 **실제로 동작한다.** 파형은 마이크 입력 레벨이고, 인용문은 인식 결과이며, 진행 막대의 앞 두 칸(`음성 수신`·`STT 변환`)은 실제 상태를 따라간다.

**뒤 세 칸은 두 갈래다** (2026-08-31 · 시나리오 대본):

- 문장이 **대본 라이브러리에 매칭되면** `대본` 배지로 바뀌고 문구는 `의도 분석 → 대본 조회` ·
  `마일스톤 분리 → 대본에서 읽음` · `태스크 생성 → 대본에서 읽음`이 된다. **어느 키워드가 맞아서
  어느 대본이 골라졌는지**가 그 자리에 뜬다. 이것은 LLM이 아니라 **키워드 대조**다 —
  대본 세 편은 `scenarios/MSN-260831-0*.json`, 매처는 `src/scenarios/matcher.ts` 하나이고
  게이트웨이와 브라우저가 같은 파일을 쓴다. 맞는 대본이 없으면 `no_script_match`로 거부된다 —
  억지로 고르지 않는다.
- 매칭이 없으면 지금처럼 `목` 배지다 — `VZ-G-01`·`VZ-G-02`이고 로컬 LLM이 필요하다.
  나중에 LLM이 들어오면 대본 조회는 그 뒤의 **대조군·시연 안전망**으로 남는다. 배지 이름을
  지금 갈라 둔 이유다(REQ-1207의 정신).

인식 결과는 **고칠 수 있고, 원문과 수정본을 둘 다 보관한다**(`REQ-1303`). 원문만 남기면 오인식을 놓치고 수정본만 남기면 STT 성능을 평가할 수 없다.

### 파이썬 환경

STT는 별도 파이썬 프로세스다(faster-whisper는 CTranslate2 런타임이라 브라우저에서 돌지 않는다). **Python 3.10 이상**이 필요하다.

```powershell
cd viz-debugger\stt
py -3.10 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

이 `.venv`가 있으면 `npm run dev`가 STT 서비스도 함께 띄운다. 자세한 것은 [stt/README.md](./stt/README.md).

**모델 최초 다운로드는 오래 걸린다.** 기본 모델 `large-v3-turbo`를 첫 요청에서 1.5 GB 안팎 내려받으므로, 첫 인식이 몇 분 걸려도 실패가 아니다. 두 번째부터는 캐시된다.

### STT 서비스를 안 띄웠을 때

**화면은 그대로 뜬다.** 음성 기능만 꺼지고, 무엇이 왜 꺼졌는지 패널에 문구가 남으며, **문장을 직접 넣는 경로는 열려 있다**(`VZ-C-02`·`VZ-G-01`). 화면 전체가 죽거나 무한 로딩에 걸리지 않는다. `npm run verify:no-stt`가 이걸 검사한다.

*2026-09-01* — 그 문구에 **주소와 실패 사유**가 함께 뜬다. 「서비스가 떠 있지 않습니다 (…8801)」와 「서비스는 떠 있는데 브라우저가 막았습니다 (CORS)」는 고치는 방법이 전혀 다른데, 브라우저의 `fetch` 는 둘을 **같은 `TypeError`** 로 던진다 — `probe()` 가 실패 경로에서 `mode:'no-cors'` 로 한 번 더 던져 가른다. **STT 가 안 뜨는 흔한 원인은 STT 가 아니다** — `viz-debugger/stt/README.md` 의 「먼저 볼 것」을 보라.

## 임무 기록 — 판마다 파일로 남는다 (2026-09-14)

**새로고침해도 리허설 기록이 남는다.** DB 가 붙기 전까지 `npm run dev` 가 띄운 개발 서버가 저장소 루트의
`mission-history/` 에 판마다 쓴다(창구 `scripts/mission-records.mjs`, 기록기 `src/record/recorder.ts`).

```
mission-history/
  260914/                        임무를 실행한 날짜 (이 노트북의 시계)
    153012_MSN-260909-01/        시작 시각 + 임무 id — 한 판
      mission.json               어떤 임무였나 — 임무 정의 전체 · 시작/끝 · 결과 · 노드 셈 · 경로 요약 · 접속 주소
      progress.json              어떻게 진행됐나 — 기록 열 · 여덟 칸 프레임 · 로봇 명령과 응답 로그 · 탐지 결과·근거·경로
                                 · 탐지 로그 · 준비 단계(도면·방위) · 알림 · 로봇 촬영 목록 · 그림 저장 결과
      images/detect/             탐지 그림 — 각도 원본 · 상자 입힌 것 · 잘라낸 것 · path_overlay · map
      images/robot/              로봇이 찍어 보낸 원본 — rot_000.jpg … rot_315.jpg
```

- **도는 동안 계속 쓴다** (1.5초마다 바뀐 것만). 끝 표시 없이 새로고침·충돌로 끊긴 판도 거기까지 남고,
  목록에 「끝 표시 없음」으로 뜬다. 끝나면(완료·실패·정지) 곧바로, 새 임무·처음부터·초기화 직전에도 한 번 더 쓴다.
- **시작을 누른 판만** 폴더가 생긴다. 승인만 하고 끝낸 판은 안 남는다.
- 탐지 그림은 받는 즉시 뜬다 — 탐지 창구가 새 판을 시작할 때 지우기 때문이다. 아직 없는 그림은 30초쯤 다시 시도한다.
- 폴더는 `.gitignore` 에 들어 있다(그림이 있어 무겁다). 다른 PC 로 옮기려면 폴더째 복사한다.
  위치를 바꾸려면 `npm run dev` 전에 `MISSION_RECORDS_DIR` 을 지정한다.

**다시보기.** 상단 `◷ 임무 이력`(또는 리플레이 화면 왼쪽 기둥)에 날짜별로 판이 뜨고, 줄마다 `다시보기` 가 있다.
누르면 그 판의 기록을 저장소에 **도로 채워 같은 화면**으로 그린다 — 노드 상태·여덟 칸·액션 아이템의 로봇 명령과
탐지 로그·경로 산출 과정·2D 맵·탐지 영상이 모두 그 판의 것이고, 슬라이더로 되감는다. 다시보기 중에는 로봇에
아무것도 안 보내고(승인·시작이 안 되살아난다), 지금 로봇의 응답을 섞지 않으며, 또 기록되지 않는다.
`다시보기 닫기` · 새 임무 · 초기화로 빠져나온다. 액션 아이템의 로그는 슬라이더와 무관하게 그 판 전체를 보여 준다.

`npm run verify:mission-record` 가 창구(폴더 밖 쓰기 차단) · 기록 · 봉인 · 다시보기를 실제로 흘려 검사한다.

## 화면에 뜨는 것 중 무엇이 진짜인가

**앱을 그냥 띄우면 남이 줄 데이터 자리가 「연결 예정」 카드로 뜬다.** 카드마다 넷이 적혀 있다 —
무엇을 기다리는가 · 누가 보내는가(파트와 상대 요구사항 ID) · 우리 쪽 자리(`VZ-*`) · 어느 평면으로 오는가.

빈칸이 아니라 카드인 이유는, 빈칸은 "우리가 안 만들었다"로 읽히고 카드는 **"못 받았다 · 누가 주면 된다"**로
읽히기 때문이다. 문구는 [src/shared/pendingSources.ts](./src/shared/pendingSources.ts) 한 곳에 모여 있다.

| | 화면에서 |
|---|---|
| 남이 줄 데이터 (영상·탐지·장치 상태·위험도·지표·감사·명령 결과·레지스트리·역할·카탈로그) | **자리표시** 19곳 |
| 우리가 만드는 목 (임무 시나리오·8상태·되감기·결함 주입) | 그대로 그린다 — **논문 측정 대상**이라 자리표시로 바꾸지 않는다 |
| 실제로 동작하는 것 (STT · 명령 발행 · 재접속과 구독 복원) | 진짜다 |

**목 게이트웨이는 끄지 않았다.** 여전히 8790에서 발행하고 데이터 계층도 여전히 받는다 —
바뀐 것은 그리는 층뿐이라 `verify:one-gateway` 가 그대로 통과한다.

상단 바의 **모드 스위치**(2026-08-31 사이트 개선)에서 `목·개발`을 고르면 예전처럼 그려진다.
**시연 중에는 켜지 말 것** — 켜면 화면 맨 위에 붉은 띠가 깔리고 자리마다 목 배지가 붙는다.
`시나리오 ▾`는 대본의 **정지 미리보기**(t=0 화면)다 — 재생은 여전히 승인(VZ-U-07) 뒤다.
화면의 설명 문단은 우상단 `?`로 들어갔다 — **캔버스의 설명서**이고, 확대가 열려 있으면 **그 노드의 설명서**다.

**시나리오 모드에서는 화면이 대본을 따라간다** (2026-09-01). 세 층이다 —
① 대본이 안 쓰는 **뷰 노드**는 팔레트에서 흐려지고 `· 이 대본엔 없음` 이 붙는다(막지는 않는다).
② 대본이 안 쓰는 **패널**은 `PanelGate`/`TabGate` 가 제목·버튼 줄·표까지 통째로 접고 한 장짜리
안내로 바꾼다 — 1·2편은 제어 노드, 3편은 영상 노드가 접힌다. ③ 남은 **자리**는 대본 값이거나
「이 대본에는 해당 없음」이다. 축→노드·패널→축 표는 `src/scenarios/axes.ts` 하나에 있고
`verify:tab-scope` 가 표와 실제 지정이 어긋나면 실패시킨다.

이식·STT·자리표시 관련 다섯 가지가 무엇을 잡는지:

| 스크립트 | 무엇을 잡는가 |
|---|---|
| `verify:stt-port` | 이식한 `stt/engines/*.py`가 `stt-lab` 원본과 **바이트 동일한가** (출처 주석 제외). 두 벌이 조용히 갈라지는 것을 막는다 |
| `verify:voice-audit` | 음성으로 발행된 명령에 `voice` 감사 필드가 빠지면 **실제로 거부되는가**. 통과한 뒤에도 세 수치가 **각각** 실리는가 (`REQ-1305`) |
| `verify:no-stt` | STT가 전부 실패하는 상태에서 화면이 뜨고 수동 입력이 살아 있는가. `probe()` 가 **실패 사유(주소 포함)를 버리지 않는가**, 그 사유가 `note` 에만 실리고 켬/끔 판단은 바뀌지 않는가 *(260901)* |
| `verify:one-gateway` | **목 게이트웨이가 하나이고 그 하나가 화면 전부를 채우는가.** 화면만 옮기면 이식본이 텅 빈 채로 뜨는 것이 이식에서 가장 놓치기 쉬웠다 |
| `verify:placeholder-default` | **앱을 그냥 띄우면 남의 데이터 자리가 자리표시인가.** 자리표시마다 무엇·누가·우리 자리·평면 넷이 다 찼는가. 표만 채우고 화면을 안 고친 것도 잡는다 |
| `verify:script-library` | **대본 세 편이 registry.json 세계 위에 있는가.** cast·세계 채널·명령의 장비가 전부 실재하고, 제목에 하드웨어 어휘가 없고, 평가 태스크마다 근거값이 있고, 세 문장이 각각 자기 대본에만 맞는가 |
| `verify:scenario-mode` | **대본 재생이 자리표시 기본값을 깨뜨리지 않는가.** 기본은 여전히 placeholder, 진입 경로는 둘(모드 스위치의 **정지 미리보기** `playing:false` · 승인 **재생** `playing:true` — **재생**만 승인 뒤다), 끄는 경로는 셸 하나, cast 밖은 자리표시, 배지는 끌 수 없다. 미리보기는 **초기 조건 + t=0 프레임**만 반영하고 trace 발행 0건 — 3편 미리보기 뒤 수문 개도율이 대본의 `initial`(100% 열림)과 맞는가까지 본다 *(260901)*. **일반 모드에서는 아무것도 접히지 않는가**와 안내줄이 재생 머리를 따라가는가도 여기서 잡는다 |
| `verify:layout` | 드래그로 노드와 연결선이 함께 움직이는가. **계산된 배치가 주어진 폭 안에 들어오는가** *(260901 확장)* — 대본 3편 × 임무 전체·마일스톤별 × 폭 1120/1280/1440/1920px 에서 노드가 화면 밖으로 나가거나 겹치지 않아야 한다. **잰 높이 안에 들어오는가** *(260904 확장)* — 창 1366×768~2560×1440 에서 높이가 허락하면 그 안에 들어오고, 모자라면 더 접지 않으며, 한 밴드에 다 들어가는 그래프는 접지 않는다. 배치는 **DAG 하나**다(§7.10). 접지 않은 배치가 3,290px 로 걸리는 음성 대조군 포함 |
| `verify:node-scope` | **시나리오가 화면을 끌고 가는 대응이 두 곳에 손으로 적히지 않았는가** *(260901 `tab-scope` → 260903 개명)*. 축→노드 표(`AXIS_NODES`)와 패널→축 표(`SCENARIO_PANELS`)를 양방향으로 대조하고, 화면의 `PanelGate`·`NodeGate` 가 그 표의 id 만 쓰는지, 표의 패널을 전부 누군가 접는지 본다. 표의 종류 id 가 **등록된 렌더러**와 같은지도 본다(이름의 원천은 렌더러 하나다). 세 편의 「쓰는 노드」(1·2편 장치·지표·영상 / 3편 장치·제어·지표)도 못으로 박혀 있다 |
| `verify:canvas-persist` | **놓아 둔 것이 사라지지 않는가** *(260903 신설)*. 구성 보존 3층(사용자 → 대본 기본 → 빈 캔버스) · 마일스톤별 슬롯 · 실패 셋(저장소 막힘 · 연결한 태스크 소실 → 전역 강등 · 스키마 변경) · **창 폭 변경·보기 범위 전환이 뷰 노드를 지우지 않는가** *(260904 — 계기가 「DAG↔트리 전환」에서 옮겨 왔다. 토글은 없어졌지만 규칙은 살아야 한다)* |
| `verify:view-nodes` | **주입 경계와 deps 분리** *(260903 신설)*. 캔버스가 `tabs/`·`shell/` 을 모르는가 · 통합 진입점이 실제로 주입하는가 · 팔레트가 종류를 손으로 적지 않는가 · 뷰 노드가 `deps` 에 들어가지 않는가 · 영상 구독이 참조 계수인가 |
| `verify:no-tabs` | **탭이 없고 확대가 탭이 아닌가** *(260903 신설)*. 탭 바·`TabView`·`TabGate`·감춘 무대가 코드에 없는가 · 확대가 캔버스를 교체하지 않는가(오버레이·반투명 배경) · 닫으면 같은 자리인가 · 확대가 한 번에 하나인가 |

다섯 다 **음성 대조군**을 포함한다 — 검사를 무력화한 사본이 반드시 실패로 잡히는지까지 확인한다. 검사가 아무것도 못 잡은 채 통과하던 일이 실제로 있었다(`reports/2026-08-28_1036_통합구현_검토.md` B항).

# gray box 탐지 학습 + 크기 기반 거리 (2026-10-27)

door 랜드마크를 시연 장소의 회색 천 박스(가로 59.3 × 깊이 21 × 높이 39cm)로 바꾸기 위한 1차 학습.
데이터: `20261026_211320/` 로봇 카메라 4572장(sha1 고유 3493장, 같은 박스를 여러 각도에서 촬영). **정답 라벨도 실측 거리도 없다.**

## 1. 라벨 (pseudo-label)

GroundingDINO에 `"gray box."`만 질의 → 후보 전체를 박스 실측 치수·색으로 걸러 최고점 선택 (`build_dataset.py`).

| 조건 | 근거(육안 감사) |
|---|---|
| ① 가로세로비 0.49~1.77 (21~62.9cm ÷ 39cm, ±10%), 좌우/아래 끝에 잘리면 해당 한계 해제 | 최고점 그대로 쓰면 무작위 32장 중 5장 오답 |
| ② 아랫변 y2 ≥ 0.6H (바닥 위) | 위쪽 소품·장식 |
| ③ 윗변 y1 ≥ 80 | 박스+칸막이 한 덩어리(윗변 y≈44) 175장 |
| ④ crop 색상 H 중앙값 110~160 | 갈색 종이상자(H 18~22) 다수. 회색 박스는 이 카메라에서 H 125~144(보랏빛). **이 방·이 카메라 값** |
| ⑤ 높이 ≥ 65px | 책상 밑 검은 가방(13/15). 대가: 이 영상보다 먼 박스는 라벨 없음 |

결과: 양성 3430장(학습 2915 / 검증 515, 시간 10구간 중 3·8구간이 검증), 판단 보류 34장.
최종 감사: 무작위 양성 32/32, 최고점에서 바뀐 라벨 24/24 정답(`audit2_*.jpg`).

## 3. 크기 기반 거리 (`fit_distance.py`)

박스가 바닥에 서 있으면 높이 39cm는 yaw와 무관 → `distance_cm = k / h_px × (1 + a·r²)` (r = 화면 중심 대비 반경, a = 어안 보정).
정답 거리가 없어 k·a는 **같은 프레임의 UniDepth + 사용자 실측 3차 보정식 거리에 맞췄다** — 절대 cm 정확도는 그 보정식을 넘지 못한다.

| | 값 |
|---|---|
| 맞춘 계수 | k = 3981, a = 1.58 (함의 초점거리 102px; 핀홀만 쓰면 127px) |
| UniDepth 대비 오차 (검증 구간) | 중앙값 22%, p90 31% |
| **인접 프레임(≤0.15초) 거리 흔들림** | 크기 기반 중앙값 **0.23%** (p90 1.2%) vs UniDepth **1.35%** (p90 6.4%) — 2132쌍 |
| 쓸 수 없던 프레임 | 박스가 crop 위/아래 끝에 닿음 766장 → 거리 내지 않음(`n/a (cut)`) |

- 두 방법이 22% 어긋나는 것은 상당 부분 UniDepth 쪽 흔들림이다(같은 장면에서 28~45cm로 움직임). 크기 기반이 약 6배 안정적.
- **절대 스케일은 미검증**: 맞춘 초점거리(102~127px)와 UniDepth가 스스로 추정한 fx(중앙값 189px, 원본 px)가 1.5배 다르다. 어느 쪽이 맞는지는 실측 없이 못 가린다.

## 4. 실측 거리 검증 (2026-11-01, `box_meter/` 14장, `fit_distance_gt.py`)

사용자가 복도(학습과 다른 장소)에서 박스 정면 50/100/150/200cm(각 1~3장) + 옆면(21cm 면이 보이게 돌림) 50~200cm 각 1장을 찍었다. 파일명 = 실측 거리.

**거리 계산식** — `d = k / h_px − c` (c = 실측 기준점과 카메라 광학 중심의 차). 한 거리를 통째로 빼고 맞춰 그 거리를 예측(leave-one-distance-out):

| 계산식 | 2차 모델·입력 512 (50~200cm, 9장) | 3차 모델·입력 256 (50~150cm, 8장) |
|---|---|---|
| 이전 잠정 계수(UniDepth에 맞춘 값) | 평균 18.1cm / 최대 43.8cm | 평균 13.7 / 최대 27.6 |
| 핀홀 `k/h` | 평균 9.2 / 최대 16.1 | 평균 7.2 / 최대 12.3 |
| **`k/h − c`** | **평균 0.4 / 최대 1.0** (k 5640, c 10.9) | **평균 0.5 / 최대 1.1** (k 5408, c 8.0) |
| 참고: UniDepth + 보정식 (2차·256으로 잡힌 6장) | 평균 15.2cm, 150cm에서 −31cm(보정식 유효범위 밖) | |

- 옆면 50cm도 49.4~50.7cm로 맞았다 → 높이만으로 거리를 내는 방식이 보는 방향과 무관하다는 것이 실측으로 확인됨.
- k·c는 검출기가 박스를 얼마나 꽉 잡는지에 따라 달라진다(위 두 열). **최종 검출기·입력 크기로 다시 맞춰야 한다.**
- 어안 보정항(a·r²)은 못 정했다 — 14장 모두 박스가 화면 중앙 근처(r 0.19~0.26). 화면 가장자리에서의 정확도는 미검증.

**탐지는 멀어지면 실패한다**

| | 2차·256 | 2차·512 | 3차(크기 변형 0.1~1.9배)·256 |
|---|---|---|---|
| 정면 50/100/150/200cm | ✔ / ✔ / ✗(0.17점) / ✗ | ✔ / ✔ / ✔ / 1장만 | ✔ / ✔ / ✔ / ✗ |
| 옆면 100/150/200cm | ✔(0.38) / ✗ / ✗ | ✗ / ✗ / ✗ | ✗ / ✗ / ✗ |
| 원래 영상: 한 장에 여러 박스 / IoU 중앙값 | 0 / 0.989 | **975장 / 0.842** | 4 / 0.982 |
| 다른 장소 오탐 (69장) | 0 | 3 | 2 |

- 원인: 학습 라벨이 박스 높이 65px 이상뿐(이 영상에 먼 박스가 없고, 가까운 검은 가방을 거르려고 건 조건). 200cm 박스는 ~27px.
- 입력 키우기(512)는 원래 영상을 망가뜨리고, 크기 변형만으로 작은 박스를 흉내 내는 것(3차)도 효과가 없었다.
- **GroundingDINO는 놓친 6장(옆면·200cm)을 전부 0.48~0.56점, 정확한 위치로 잡았다** → 먼 거리를 찍은 영상만 있으면 같은 라벨 생성 방식으로 학습 데이터를 만들 수 있다.

## 한계 / 다음 단계

1. ~~거리 실측이 필요하다~~ → 4절에서 완료(50~200cm 정면 기준 오차 1cm 이내). 남은 것: 화면 가장자리(좌·우로 비켜선 위치) 실측, 최종 검출기로 k·c 재보정.
1-1. **먼 거리(1.5~3m)·옆면이 찍힌 영상이 필요하다.** 로봇이 박스에서 멀어졌다 가까워지며 주위를 도는 영상이면 된다. 그 영상은 라벨 조건 ⑤(65px)를 낮춰야 하는데, 그 대신 막고 있던 검은 가방 같은 오답을 다른 조건으로 걸러야 한다.
2. 가까운 장면은 박스 아랫부분이 테두리 crop(237×241) 밖으로 나가 높이를 못 잰다. 원본 464×400에는 더 아래까지 찍혀 있으므로 거리 계산만 원본 좌표에서 하면 `n/a` 일부를 살릴 수 있다(검출은 crop, 높이는 원본).
3. 학습이 이 방 한 곳·한 조명이다. 시연 장소 프레임으로 재검증이 필요하고, ④ 색상 조건은 장소마다 다시 재야 한다.
4. 파이프라인 미연결: `class_finder_service`의 provider·`LOCALIZATION_CLASSES`·`navigate_to_target_service`는 건드리지 않았다.

## 2. 공통 틀과 대조 — `node.py` 의 가정 A1~A6

이 저장소에 `~/hw/pi` 코드가 없어서, 같은 일을 하는 가시화 쪽 `viz-debugger/drone/sar_pass/agent.py` 의 규약을 따랐다. 그것도 가짜 노드로만 시험된 것이다. **`~/hw/pi/common/node.py` 와 `~/hw/pi/drone/drone_node.py` 를 읽고** 아래를 하나씩 확인한다. 틀린 것은 `node.py` 를 고치고, `test_flight_runner.py` 의 `FakeDroneNode` 도 실물 모양으로 맞춘다.

| | 가정 | 확인할 것 | 틀리면 고칠 곳 |
|---|---|---|---|
| A1 | 클래스 속성 `ACTIONS: dict[str, handler]` 의 키가 Capability 로 나간다 | Capability 를 만드는 자리 | `FlightRunnerNode.ACTIONS` |
| A2 | `handler(node, params)` 는 `(stage, detail)` 를 내는 제너레이터. 마지막 `("completed", {숫자})` 가 result | 핸들러를 부르는 자리, result 를 만드는 자리 | `act_start` · `act_stop` · `act_emergency` |
| A3 | `validate(action, params)` 가 Acceptance 전에 망 스레드에서 불린다. 거기서 `code` · `message` 를 가진 예외를 던지면 rejection 이 된다 | 거절을 만드는 자리 — 예외 클래스 이름 · 속성 | `core.Rejected` (필요하면 공통 틀의 예외를 상속) |
| A4 | `node.publish(topic, body, qos=, retain=, allow_spool=)`, `node.base` = `zoneA/drone/<id>`, `node.identity.entity_id` 등 | 시그니처와 속성 이름 | `default_runner()` · `node_identity()` |
| A5 | `common.node.main(cls)` 가 진입점 (SIGTERM → 정상 종료) | `main` 의 모양 | `node.main()` |
| **A6** | **핸들러가 지금 명령의 `command_id` 를 아는 길** | params 에 실려 오나, 노드 속성에 있나, 핸들러 인자로 오나 | **`command_id_of()`** |

**A6 이 가장 중요하다.**

- 가시화는 `flight_run.run.command_id` 로 「내가 보낸 dry-run 이 코드 0 으로 끝났다」를 짝짓는다. 이게 맞아야 「비행 시작」 버튼이 열린다.
- 지금 `command_id_of()` 는 `current_command_id` · `command_id` · `current_command.command_id` 를 찾아보고, 못 찾으면 `None` 이다. `None` 이면 **버튼이 영영 안 열린다.**
- 공통 틀에 길이 없으면, 공통 틀을 고치지 말고 다음 순서로 찾는다.
  1. 감싸개에서 명령을 받는 메서드를 하나 덮어써 command_id 를 노드에 잠깐 적어 둘 수 있는지 본다.
  2. 그것도 안 되면 사용자에게 알린다.

확인 결과(무엇이 맞았고 무엇을 고쳤는지)를 §6 보고서에 표로 남긴다.

## 3. 노드 없이 실행기만 시험

드론 노드는 그대로 둔 채로 한다. `cli.py` 는 `node.py` 를 쓰지 않는다.

```bash
cd ~/drone
./venv/bin/python -m pytest flight_runner -q                 # 18 passed 이어야 한다 (Linux)
sudo loginctl enable-linger physical                          # 사용자 systemd 를 로그인 없이 띄워 둔다
systemctl --user list-units | head -3                         # 응답이 와야 한다
```

### 3-1. FC 없이 (기체 전원 끈 상태 또는 mavlink-router 멈춤)

```bash
R="./venv/bin/python -m flight_runner"
$R start pattern=0 side=0 altitude_m=3 length_m=3 speed_mps=1 passes=1 dry_run=1
#  → [연결] … 뒤 연결 시간 초과(30초), 「--- 끝: 종료 코드 1」
$R start pattern=0 side=0 altitude_m=50 length_m=3 speed_mps=1 passes=1 dry_run=1
#  → test_sar_rtk.py: error: --altitude … , 「종료 코드 2」
$R start pattern=0 side=0 altitude_m=3 length_m=3 speed_mps=1 passes=1 dry_run=0 confirmed=1 --no-follow
sleep 3 && $R stop && $R follow
#  → 연결을 기다리던 스크립트가 SIGTERM 을 받아 끝난다 — 코드 1, 「중단됨」 류 문구
pgrep -a mavsdk_server                                         # ★ 비어 있어야 한다 (남으면 보고서에 적을 것)
$R emergency land && sleep 2 && $R status
systemctl --user list-units 'test-sar-rtk-*' 'emergency-land-*' --all   # 남은 유닛 없어야 한다
```

### 3-2. FC 연결 · 실기체 dry-run (arm 하지 않는다)

```bash
$R start pattern=0 side=0 altitude_m=3 length_m=3 speed_mps=1 passes=1 dry_run=1 --mqtt 127.0.0.1:1883 --device x500-001
```

- 「[미션] 대조 일치 ✔」 → 「[dry-run] 여기서 끝낸다」 → 종료 코드 0 이어야 한다.
- `--mqtt` 를 붙였으므로 가시화 「비행 제어」 탭 아래 「진행 · 출력」 칸에도 같은 줄이 뜬다.
  - 이때 화면의 버튼은 아직 닫혀 있는 것이 정상이다. 선언(Capability)은 §4 뒤에 온다.

## 4. 설치와 연동 확인

```bash
cd ~/drone/flight_runner/deploy
./install.sh                          # 확인만 — ✗ 가 없어야 한다
sudo ./install.sh --install --dry-run # 할 일 보기
sudo ./install.sh --install           # linger · 출력 폴더 · /etc/flight-runner.env · 덮어쓰기 → drone-node 재시작
journalctl -u drone-node -n 80 --no-pager | grep -E "비행 실행기 준비|Traceback|Error"
mosquitto_sub -h 127.0.0.1 -t 'zoneA/drone/+/flight_run' -C 1 -v     # retained 1건이 와야 한다
```

- drone-node 가 안 뜨면 **바로 되돌린다**: `sudo ./install.sh --uninstall`. 가시화의 드론 상태가 같이 끊기기 때문이다.
- 그런 다음 journal 의 Traceback 으로 §2 가정을 다시 본다.
- 가시화에서 확인할 것: 드론 상세창 「비행 제어」 탭 머리의 세 칩(`rtk_test_start` · `rtk_test_stop` · `rtk_test_emergency`)이 「선언됨」이어야 한다.

### 덮어쓰기가 하는 일 (`deploy/60-flight-runner.conf`)

- `ExecStart` → `python -m flight_runner.node --node drone.drone_node:DroneNode`. `PYTHONPATH=/home/physical/drone` 을 더한다.
- 비행 스크립트는 **사용자 systemd 유닛**(`systemd-run --user`)으로 뜬다.
  - 그래서 drone-node 가 watchdog 으로 재시작돼도 스크립트는 죽지 않는다. 같은 cgroup 이면 SIGTERM 을 받아 비행 중 RTL 을 보냈을 것이다.
  - drone-node 가 `NoNewPrivileges=yes` 라 sudo 를 못 쓰므로 시스템 관리자가 아니라 사용자 관리자로 간다.
  - 이를 위해 `XDG_RUNTIME_DIR` · `DBUS_SESSION_BUS_ADDRESS` 를 넣는다.
- `ProtectSystem=strict` 안에서 출력을 쓰도록 `ReadWritePaths=/home/physical/cansar_logs` 를 연다.
- 확인할 것: `ProtectSystem=strict` 아래에서 `/run/user/<uid>/bus` 연결이 되는지. 안 되면 덮어쓰기에 `ReadWritePaths=-/run/user/<uid>` 를 더해 본다.

## 5. sar_pass.agent 가 이미 깔려 있으면

둘 다 「DroneNode 를 상속해 action 을 덧붙이는」 감싸개라 겹쳐 쓸 수 있다.

```
with_flight_runner(with_sar(DroneNode))
```

- 다만 지금 `--node` 는 `module:Class` 만 받는다. 겹치려면 작은 진입 모듈이 하나 더 필요하다.
- 만들기 전에 사용자에게 어느 쪽을 쓸지 묻는다. sar_pass 는 오프보드 제어라 이 실행기와 비행 방식이 다르다.

## 6. 시험 목록과 보고

요청 문서 §5 의 여섯 항목을 **노드 연동 상태에서**(가시화 화면 또는 `mosquitto_pub`) 돌린다.

| # | 시험 | 기대 |
|---|---|---|
| 1 | FC 없이 `rtk_test_start` dry_run=1 | 연결 실패 출력, `exit_code 1` 이 `flight_run` 에 |
| 2 | `altitude_m=50` | `exit_code 2`, `ap.error` 문구가 `lines` 에 |
| 3 | 실행 중 `rtk_test_stop` | **주 프로세스만** SIGTERM — `[중단] 사용자 중단 (Ctrl+C/SIGTERM)`, mavsdk_server 남지 않음 |
| 4 | 실행 중 `sudo systemctl restart drone-node` | **스크립트가 죽지 않고**, 재시작 뒤 `flight_run` 이 같은 run_id · 같은 seq 로 이어진다 |
| 5 | 실기체 dry-run | `[미션] 대조 일치 ✔` → `[dry-run] 여기서 끝낸다` → `exit_code 0`, **화면의 「비행 시작」이 열린다**(A6 확인) |
| 6 | 동시 시작 · 확인 없는 비행 | `already_running` · `not_confirmed` 거절 |

결과는 다음 보고서로 남겨 이 브랜치에 커밋한다.

- 파일: `drone/flight_runner/REPORT_pi3_<날짜>.md`
- 넣을 것
  - 출력 원문
  - §2 대조표 결과
  - 고친 파일 목록
- 가시화가 그 보고서로 화면 판정을 맞춘다. 특히 **스크립트 로그 문구가 바뀌면 반드시 적는다.** 화면은 `[미션] 진행 #n` · `PASS n START` 같은 원문을 읽는다.

## 참고

- 가시화에는 실물 없이 화면을 확인하는 **가짜 드론**(연결 관리 → 「가짜 드론」)이 있다. 이 실행기를 흉내 내므로, 화면 쪽 동작을 볼 때는 Pi 없이 그쪽을 쓰면 된다.
- **손 도구(`python -m flight_runner`)는 주인을 스스로 가린다.**
  - 덮어쓰기(`/etc/systemd/system/drone-node.service.d/60-flight-runner.conf`)가 있으면 노드 안의 실행기가 주인이다.
    - 이때 손 도구는 `status` · `follow`(보기만 — 상태 파일 · 유닛을 안 건드린다) · `stop`(신호만)만 한다.
    - `start` · `emergency` 는 거절한다. 같은 상태 파일(`~/cansar_logs/runner/runner_state.json`)을 둘이 쓰면 서로 덮기 때문이다.
    - SSH 에서 급히 내려야 하면 `scripts/emergency_land.py` 를 직접 실행한다.
  - 설치 전에는 손 도구가 주인이다. `--owner` 는 노드가 꺼져 있을 때만 쓴다.

 # 작업 프롬프트 — pi3 드론 브리지: 가시화와 MQTT 연결 (2026-09-21)

> 라즈베리파이 `pi3`의 AI 에이전트에게 붙여 넣는 용도. 같이 내릴 명령은 `작업명령_드론가시화연결_260921.md`.

---

## 배경

`pi3`는 X500 v2 드론의 컴패니언 컴퓨터다. 지금까지 한 일(`~/drone/PROGRESS.md`):
- FC(코아 H743, PX4) ↔ `/dev/ttyAMA0` 921600, **FC 쪽 포트는 TELEM2** (`MAV_1`, Onboard). TELEM1은 무선 Air Unit
- 부팅하면 `drone-detect` → `drone.target`(mavlink-router + linkmon)이 자동으로 뜬다
- 지상국 QGC가 Tailscale `100.85.243.54:5760`으로 접속 확인됨
- 최종 보고서: `~/drone/SETUP_REPORT.md` (0~7단계 통과)

### 이미 있는 것 — 새로 만들지 말고 쓴다

| 있는 것 | 이번에 쓰는 법 |
|---|---|
| mavlink-router 엔드포인트 5760(QGC) · 14540(MAVSDK 제어 자리) · 14541(linkmon) · 14542(detect) | 브리지용으로 **14543을 하나 추가**. 14540은 나중 제어 코드 자리라 쓰지 않는다 |
| `~/drone/scripts/dronelink.py` | 기체 heartbeat 판별(`is_vehicle_heartbeat`), PX4 모드 디코딩 등. **다시 짜지 말고 가져다 쓴다** |
| `~/drone/state/mode` (`drone`/`none`) | 브리지가 "FC 링크 없음"을 판단하는 근거 중 하나로 쓴다 |
| FC 스트림 (Onboard 모드) | ATTITUDE 100Hz, SYS_STATUS 5Hz, GPS_RAW_INT 10Hz, BATTERY_STATUS 0.6Hz가 **요청 없이 이미 들어온다**. 배터리는 SYS_STATUS 기준, BATTERY_STATUS는 보조 |
| `/etc/drone-node.env` | `MQTT_HOST=192.168.50.172`(pi7)로 적혀 있다. **이번 구조에선 브로커가 pi3 자신이므로 `127.0.0.1`로 바꾼다.** 기존 pi7 값은 주석으로 남기고, 백업 후 수정 |

### 브리지는 FC로 아무것도 보내지 않는다

FC가 Onboard 모드로 필요한 메시지를 이미 흘려 준다. 그러니 이번 브리지는 **송신 0바이트, 읽기 전용**으로 만든다. `linkmon.py`와 같은 수준이다. 스트림 요청이 꼭 필요해지면 그때 멈추고 보고한다.

### 경로 확인

pi3 보고서 끝에는 다음 작업 경로가 "웹 → 서버 → MQTT → 라즈베리파이"로 적혀 있다. **이번에는 서버를 거치지 않는다.** Go1과 같이 웹이 라즈베리파이의 브로커에 직접 붙는 온디바이스 직통이다.

이번 목표는 **가시화 웹에서 드론의 연결 상태, 배터리, 드론 상태를 볼 수 있게 하는 것**이다. **제어 명령은 이번 범위가 아니다.**

### Go1과 같은 방식으로 한다

Go1(`pi7`)은 이렇게 붙어 있다.

| 항목 | Go1 (`pi7`) |
|---|---|
| 브로커 | **라즈베리파이 자체에서 mosquitto 실행.** 1883(TCP) + 9001(WebSocket), `/etc/mosquitto/conf.d/hw.conf`, 익명 허용 |
| 웹 접속 | 연결 관리의 로봇 칸에 `ws://pi7.local:9001` |
| 토픽 | `terminal/go1-001/downlink`(웹→로봇), `terminal/go1-001/uplink`(로봇→웹), QoS 1 |
| 페이로드 | protobuf `Envelope` (`schema/physical_command.proto`, 저장소 `khw18033/Physical-Project-mk2`의 `HW` 브랜치) |
| 노드 코드 | `~/hw/pi/` (`common/`, `robot/`, `sensor/`) — `common/node.py`가 공통 틀, 로봇별 차이는 어댑터가 흡수 |
| 접속 시 | **Capability 자동 발행** (device_id, actions). 미선언 action은 `UNIMPLEMENTED`로 실행 전 거부 |
| clientId | `identity.entity_id` 그대로 (`go1-001`, `wl-001`) |

드론도 **똑같이** 한다. 웹은 로봇 칸 주소를 `pi7` 대신 `pi3`로 바꾸기만 하면 드론에 붙는다.

**핵심 원칙: Go1의 노드 틀을 그대로 쓰고, 드론 차이는 어댑터 한 파일로 흡수한다.** 이게 캡스톤2의 범용성 주장(신규 장비 1대 연결 = 어댑터 1파일)의 실증이다. 공통 틀을 고쳐야 한다면 고치기 전에 멈추고 이유를 보고한다.

## 규칙

1. **드론 안전**: 브리지는 FC로 아무것도 보내지 않는다(읽기 전용). arm, takeoff, land, 모드 변경, offboard, 파라미터 쓰기는 물론이고 스트림 요청도 하지 않는다. 필요해지면 멈추고 보고한다.
2. **Capability에 선언하는 action은 `ping` 하나뿐이다.** 그 외 action은 공통 틀이 `UNIMPLEMENTED`로 거부하게 둔다. 정지(`abort` 등)도 이번엔 선언하지 않는다 — 드론 정지는 조종기가 맡는다.
3. **`.proto` 스키마를 고치지 않는다.** `HW` 브랜치 소유다. 드론 상태를 실을 자리가 없으면 멈추고 보고한다(4단계 참고).
4. 기존 `drone-*` 유닛, mavlink-router 설정, Tailscale 설정은 필요한 추가(엔드포인트 1개 등) 외에 바꾸지 않는다. 바꾸면 전후를 PROGRESS.md에 남긴다.
5. 재부팅이 필요하면 먼저 말하고 확인을 받는다.
6. 보고는 한국어.

### 0단계. 조사 (바꾸지 않는다)

**0-1. Go1 노드 코드 가져오기**
- `HW` 브랜치를 `~/hw`에 clone한다. 접근이 안 되면(비공개 저장소 등) 멈추고 방법을 묻는다
- `pi7`은 지금 꺼져 있다. `pi7`에서 직접 복사하는 방법은 쓰지 않는다

**0-2. Go1이 어떻게 붙는지 코드로 확인**
- `common/node.py`: 브로커 접속, clientId, 토픽 구성, Capability 발행 토픽과 형식, 명령 수신·거부 흐름
- 로봇 어댑터가 구현하는 인터페이스(메서드 목록)
- `ping` 응답에 무엇이 실리는가 (`uptime_s` 등)
- **Go1은 상태(배터리 등)를 웹에 어떻게 보내는가.** 주기 발행인지, 어떤 토픽·메시지인지, 아니면 안 보내는지
- `/etc/hw-node.env`, `/etc/hw-robot.env`에 어떤 키가 있는가
- mosquitto 설정 `hw.conf` 내용 (저장소나 `deploy/`에 있을 것)

**0-3. 드론 상태로 무엇을 보낼 수 있는가**
14543 엔드포인트를 추가한다고 가정하고(아직 추가하지 않는다), 이미 들어오는 스트림에서 얻을 수 있는 항목을 정리한다. `telemetry_watch.py`를 실행해 실제 값을 같이 적는다.

| 분류 | 항목 | MAVLink 메시지 |
|---|---|---|
| 연결 | FC 링크 유무, 마지막 heartbeat 이후 경과 | HEARTBEAT |
| 배터리 | 전압, 전류, 잔량 % | SYS_STATUS, BATTERY_STATUS |
| 상태 | arm 여부, 비행 모드 | HEARTBEAT (base_mode, custom_mode) |
| 위치 | GPS fix 종류, 위성 수, 위치 추정 정상 여부 | GPS_RAW_INT, (EKF/ESTIMATOR_STATUS) |
| 자세 | roll, pitch, yaw | ATTITUDE |
| 경고 | FC가 보낸 STATUSTEXT 최근 몇 줄 | STATUSTEXT |

**0단계 보고**: 표로 정리하고, 특히 아래 셋을 분명히 적는다.
1. Go1의 상태 보고 방식과 그걸 드론에 그대로 쓸 수 있는지
2. 스키마 안에 드론 상태를 실을 자리가 있는지 (예: `detail` 같은 JSON 문자열 필드)
3. 어댑터 1파일로 끝나는지, 공통 틀을 건드려야 하는지

**승인받을 때까지 멈춘다.**

### 1단계. 브로커

- mosquitto 설치, Go1의 `hw.conf`와 같은 설정(1883 + 9001 websockets, 익명)
- `systemctl enable --now mosquitto`
- 확인: `ss -tlnp`에 1883·9001, 로컬에서 `mosquitto_sub`/`mosquitto_pub` 왕복

### 2단계. 드론 어댑터

- Go1 노드 틀(`common/node.py`)에 드론 어댑터를 붙인다. 위치는 Go1 어댑터와 같은 층(예: `~/hw/pi/robot/` 옆)
- 식별자: `entity_id = x500-001` (`/etc/device_id`와 같은 값), 토픽 `terminal/x500-001/downlink`·`uplink`
- 설정은 Go1처럼 `/etc` env 파일로 (`/etc/hw-node.env` 형식을 따르되 드론용 값). 브로커 주소는 `127.0.0.1:1883`
- MAVLink 입력은 mavlink-router에 **UDP 14543 엔드포인트를 추가**해서 받는다. `dronelink.py`를 가져다 쓴다
- `/etc/drone-node.env`의 `MQTT_HOST`를 `127.0.0.1`로 바꾼다 (백업, pi7 값은 주석으로)
- Capability: `ping`만 선언. 장비 종류가 드러나는 값(예: kind=`drone`)을 실을 자리가 있으면 싣는다
- `ping` 응답: Go1과 같은 형식 + FC 링크 유무
- 상태 보고: 0단계에서 확인한 Go1 방식을 그대로 따른다. 주기는 1~2Hz
- FC 링크가 끊겨도 노드는 살아 있어야 한다. 이때 상태는 "FC 링크 없음"으로 보내고, 배터리 등은 마지막 값이 아니라 **없음**으로 보낸다 (오래된 값을 현재 값처럼 보이지 않게)

### 3단계. 자동 실행

- Go1의 `robot-node.service`와 같은 결로 `drone-node.service`를 만든다
- `drone.target`과의 관계: **노드는 FC가 없어도 떠 있어야 한다.** 라우터는 드론 모드일 때만 뜨므로, 라우터가 없을 때는 `state/mode`와 수신 공백으로 "FC 링크 없음"을 판단한다. 웹이 "브로커는 붙었고 드론 노드도 답하는데 FC 링크만 없다"를 구분할 수 있어야 하기 때문. `drone.target` 밖에서 부팅 시 자동 시작으로 둔다
- 자동 실행에 제어 명령을 보내는 코드가 없음을 확인한다

### 4단계. 계약 문서

웹 쪽 AI가 읽을 문서를 `~/drone/CONTRACT_x500.md`로 남긴다. **실제 코드에서 확인한 값만 적는다.**
- 브로커 주소(이름·연구실 IP·Tailscale IP), 포트
- 토픽, clientId
- Capability 실제 페이로드(디코드한 모습)
- `ping` 요청·응답 실제 페이로드
- 상태 보고의 토픽·메시지·필드 목록, 단위, 없을 때의 표현
- 장비 종류를 알 수 있는 값과 그 위치
- 목(mock)으로 흉내 낼 수 있게 예시 페이로드 hex 몇 개

### 5단계. 검증

| 확인 | 방법 |
|---|---|
| 브로커 | 다른 PC에서 `ws://pi3.local:9001`·`ws://192.168.50.254:9001` 접속 (사용자에게 요청) |

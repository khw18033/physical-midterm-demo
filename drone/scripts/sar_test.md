# sar_test.py — SAR 레이더 캡처용 반복 직선 비행

PX4 기체(x500)를 정해진 직선 위로 같은 방향으로 여러 번 날리면서, 등속 구간에서만 레이더 캡처를 켜는 스크립트입니다.
`takeoff_land.py`(시험비행 성공)의 연결·안전 확인 흐름을 그대로 쓰고, 그 위에 경로 비행과 캡처 트리거를 얹었습니다.

> ⚠ **기체가 실제로 이륙해 100 m 직선을 여러 번 오갑니다.** 사람이 조종기를 들고 직접 실행합니다. systemd·cron 같은 자동 실행에 넣지 않습니다.

---

## 1. 비행 경로

이륙 지점을 **L** 로 두고, 고정 헤딩 방향으로 한 직선 위에 네 점을 잡습니다.

```
 L ──── 가속 20 m ──── S ════════ 등속 60 m (캡처 ON) ════════ E ──── 감속 20 m ──── X
(이륙)                 ▲ CAP_ON 생성                         ▲ CAP_ON 삭제
 0 m                  20 m                                  80 m                  100 m
```

| 점 | 위치(L 기준) | 의미 |
|---|---|---|
| L | 0 m | 이륙 지점. 매 패스의 출발점, 마지막 착륙 지점 |
| S | `--lead-in` (20 m) | 가속이 끝나는 곳. **레이더 캡처 ON** |
| E | S + `--length` (80 m) | 등속 구간 끝. **레이더 캡처 OFF** |
| X | E + `--lead-out` (100 m) | 감속해서 멈추는 곳. 패스의 끝 |

비행 순서:

```
이륙(20 m) → L 정렬
→ 패스 1: L → X  (S 에서 캡처 ON, E 에서 캡처 OFF) → L 로 복귀
→ (캡처 OFF 후 10 초 이상 간격)
→ 패스 2: L → X  (동일)                            → L 로 복귀
→ L 에서 착륙
```

비행 조건과 반영 방식:

| 조건 | 반영 |
|---|---|
| 고도 20 m 일정 | 모든 이동 명령을 home 고도 + 20 m(AMSL) 로 보냄 |
| 직선 60 m 이상, 3~5 m/s 등속 | 캡처 구간 60 m(`--length`, 60 미만 거부), 속도 5 m/s(`--speed`, 3~5 외 거부) |
| 가속·감속은 직선 구간 밖 | 앞뒤로 가속 20 m(L→S), 감속 20 m(E→X) 여유를 둠 |
| 직선 구간 동안 헤딩 = 진행 방향 | 헤딩을 처음부터 끝까지 L→X 방향으로 고정. 복귀(X→L)는 기수를 돌리지 않고 후진 |
| 같은 선을 같은 방향으로 2회 이상 | 매 패스를 L→X 로만 비행, `--passes` 기본 2(2 미만 거부) |

헤딩(=직선 방향)은 기본적으로 **스크립트를 실행한 순간 기체 기수 방향**입니다. 기체를 원하는 방향으로 놓고 실행하거나, `--heading 90`(동쪽) 처럼 직접 지정합니다.

## 2. 레이더 캡처 켜기/끄기

캡처는 `cansar.service`(`/home/physical/cansar_pi.py`)가 담당합니다. 이 스크립트는 **파일 하나를 만들고 지우기만** 합니다.

```
/home/physical/CAP_ON   있으면 캡처, 없으면 정지
```

- **켜는 시점:** 기체가 **S 를 지나는 순간** `touch` 합니다. 가속이 끝나고 등속에 들어간 직후입니다.
- **끄는 시점:** 기체가 **E 를 지나는 순간** `unlink` 합니다. 감속이 시작되기 전입니다.
- **경로 양 끝에서는 켜지지 않습니다:** 출발점 L 과 끝점 X 에서는 캡처가 꺼져 있습니다. 이 두 점 근처는 가속·감속 구간이라 지시서대로 캡처에서 뺐습니다.
- **판정 방법:** 위치를 직선에 투영한 진행 거리로 S·E 통과를 약 20 Hz 로 판정합니다(5 m/s 에서 약 0.25 m 단위).
- **간격:** 한 패스의 캡처 OFF 부터 다음 패스의 캡처 ON 까지 최소 10 초(`--gap`)를 둡니다. 그 사이 cansar 가 SDR 데이터를 옮깁니다.

**CAP_ON 이 남지 않게 하는 장치** (남으면 계속 캡처됩니다):

| 상황 | 동작 |
|---|---|
| 명령 실패·시간 초과 | 캡처 OFF → RTL(`--abort`) |
| Ctrl+C·SIGTERM | 캡처 OFF → RTL(`--abort`) |
| 비행 모드가 HOLD 밖으로 바뀜(조종기 개입, FC 의 RTL·페일세이프) | 캡처 OFF, **추가 명령 없음**(조종기/FC 에 맡김) |
| 스크립트가 어떤 이유로 끝나든 | 마지막 `finally` 에서 한 번 더 삭제 |
| 시작할 때 이전 실행의 파일이 남아 있음 | 삭제하고 로그에 경고 |

참고:
- **SDR 반영 지연:** cansar 는 파일을 계속 확인하다가 ssh 로 SDR 에 캡처를 지시하므로 실제 SDR 시작/정지는 파일보다 조금 늦습니다. 정확한 SDR 시각은 cansar 쪽 `events.csv`(Pi 시각 ↔ SDR uptime)에 남습니다.
- **실행 계정:** `cansar.service` 는 `physical` 사용자로 돌기 때문에, 이 스크립트도 **`physical` 사용자로 실행**합니다. root 로 실행하면 root 소유 `CAP_ON` 이 생겨 cansar 쪽에서 다루기 곤란해질 수 있습니다.

## 3. 실행 전 준비

1. **장소:** 이륙 지점에서 헤딩 방향으로 100 m, 고도 20 m 이상이 비어 있는 야외. 사람·장애물과 충분한 거리.
2. **FC 파라미터(QGC):**
   - 지오펜스 `GF_MAX_HOR_DIST` 가 100 m 보다, `GF_MAX_VER_DIST` 가 20 m 보다 넉넉한지
   - `RTL_RETURN_ALT` — 이상 시 RTL 이 이 고도까지 올라간 뒤 돌아옵니다
3. **서비스 상태:**
   ```bash
   systemctl status drone.target      # FC 링크 (MAVSDK 14540)
   systemctl status cansar.service    # 레이더 캡처 브리지
   ls /home/physical/CAP_ON           # "No such file" 이어야 정상
   ```
4. **배터리:** 기본 설정에서 비행 시간은 대략 3~4 분입니다(패스당 왕복 200 m + 정지·간격). 여유 있게 충전합니다.
5. **조종기:** 손에 들고 즉시 모드 전환(Position 등)으로 개입할 수 있게 합니다.

## 4. 실행 방법

모든 명령은 `/home/physical` 에서 `physical` 사용자로 실행합니다.

### 4-1. dry-run (먼저 반드시)

FC 에 연결해 위치·헤딩을 읽고 **계산된 L·S·E·X 좌표만 출력**합니다. arm 하지 않고 캡처 파일도 만들지 않습니다.

```bash
drone/venv/bin/python drone/scripts/sar_test.py --dry-run
```

출력 예:
```
[경로] 헤딩(고정) 217.5°
[경로] L  36.3500000, 127.3000000  (0m)
[경로] S  36.3498575, 127.2998642  (20m)
[경로] E  36.3494299, 127.2994568  (80m)
[경로] X  36.3492873, 127.2993210  (100m)
[경로] 고도 AMSL 87.3m (home 67.3m + 20.0m)
```

헤딩과 좌표가 현장(지도)과 맞는지 확인합니다.

### 4-2. 실제 비행

```bash
drone/venv/bin/python drone/scripts/sar_test.py
```

안전 확인 문구가 나오면 직접 `yes` 를 입력해야 진행됩니다. 이후 순서:

1. FC 연결 → 이미 arm 상태면 중단 → GPS·home 위치 정상 확인
2. 경로 계산 → 이륙 고도 설정 → arm → takeoff
3. 20 m 도달 → L 정렬 → 패스 반복 → L 복귀 → 착륙
4. 착륙 확인 후 종료

비행 중 2 초마다 `진행 거리 / 속도 / 고도` 가 출력되고, 캡처 중이면 `CAP` 표시가 붙습니다.

### 4-3. 중단

- **스크립트 중단:** 터미널에서 **Ctrl+C** 를 누르면 캡처를 끄고 RTL 합니다.
- **조종기로 개입:** 조종기로 모드를 바꾸면 스크립트는 캡처만 끄고 손을 뗍니다. 이후는 조종기로 처리합니다.

### 4-4. 주요 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--dry-run` | — | 경로만 계산·출력, arm 안 함 |
| `--heading DEG` | 실행 시 기수 방향 | 헤딩·직선 방향(0=북, 시계방향) |
| `--altitude M` | 20 | 비행 고도(home 기준) |
| `--speed M/S` | 5 | 수평 속도, 3~5 만 허용 |
| `--length M` | 60 | 등속(캡처) 구간 길이, 60 이상 |
| `--lead-in M` | 20 | 가속 구간 L→S |
| `--lead-out M` | 20 | 감속 구간 E→X |
| `--passes N` | 2 | 같은 방향 패스 횟수, 2 이상 |
| `--gap SEC` | 10 | 캡처 OFF → 다음 ON 최소 간격, 10 이상 |
| `--speed-tol M/S` | 0.5 | 캡처 구간 속도 허용 오차(벗어나면 로그 경고) |
| `--abort` | rtl | 이상 시 동작: `rtl` / `hold` / `land` |
| `--log-dir DIR` | /home/physical/cansar_logs | 로그 저장 폴더 |
| `--yes` | — | `yes` 입력 생략(안전을 이미 확인한 경우에만) |

예: 4 m/s 로 3 패스, 동쪽 방향

```bash
drone/venv/bin/python drone/scripts/sar_test.py --speed 4 --passes 3 --heading 90
```

## 5. 로그

`/home/physical/cansar_logs/sar_test_<날짜시각>.log` 에 저장되며, 모든 줄 앞에 `[time.time()]` 이 붙습니다(cansar `pi.log` 와 같은 형식이라 시각으로 바로 맞춰 볼 수 있습니다).

패스마다 남는 줄:

```
PASS 1 START t=1790857072.516 속도 4.98m/s 고도 20.1m
PASS 1 END   t=1790857084.533 속도 5.01m/s 고도 19.9m
PASS 1 SUMMARY start=... end=... dur=12.02s speed min/mean/max=4.81/4.99/5.12m/s alt min/max=19.8/20.2m cross-track max=0.6m
```

- **START / END:** 캡처 ON / OFF 시각(time.time()), 패스 번호
- **SUMMARY:** 캡처 구간의 속도·고도 범위, 직선에서 옆으로 벗어난 최대 거리
- 끝날 때 전체 패스의 `PASS n start= end=` 목록을 한 번 더 남깁니다.

확인할 것:
- **속도 경고:** `[경고] ... 속도가 5±0.5m/s 를 벗어났다` 가 있으면 등속이 아니었다는 뜻입니다. S 진입 속도 경고가 반복되면 `--lead-in` 을 늘립니다(예: 30).
- **cansar 쪽 판정:** cansar 쪽 `passes.csv` 의 패스 판정(OK / 재비행?)도 함께 봅니다.

1. **QGC 에서 .ulg 로그 받기** — Analyze Tools → Log Download → 이번 비행 로그 선택 → Download
2. 정리할 파일:
   - **비행 스크립트 로그:** `cansar_logs/sar_test_<날짜시각>.log`
   - **cansar 로그:** `cansar_logs/<날짜시각>/` (`events.csv`, `passes.csv`, `mav.csv`, `pi.log`)
   - **레이더 데이터:** `flight/iq_N.bin`, `meta_N.txt`
3. **CAP_ON 정리 확인:** `ls /home/physical/CAP_ON` 이 없어야 정상입니다.

## 7. 알려진 한계

- **등속은 FC 가 결정합니다:** PX4 위치 이동(goto/reposition)의 가속·감속은 FC 가 계획합니다. 그래서 20 m 여유 안에서 등속에 들어간다고 **가정**한 것이며, 실제 속도는 첫 비행의 SUMMARY 로 확인해야 합니다.
- **속도 명령이 거부될 때:** 속도 지정(`set_current_speed`)이 거부되면 경고만 남기고 FC 기본 순항 속도(`MPC_XY_CRUISE`, PX4 기본 5 m/s)로 비행합니다.
- **복귀 구간:** X→L 복귀는 후진 비행이며 캡처하지 않습니다.
- **시험 범위:** 가짜 드론으로 캡처 ON/OFF 시점과 모드 이탈 시 정리만 확인했습니다. 실제 FC 로 비행 시험한 기록은 아직 없습니다.

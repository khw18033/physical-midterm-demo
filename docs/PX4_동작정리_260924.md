# PX4 동작 정리 — 제어·모드·기능과 라즈베리파이 연동 시 주의점

작성 2026-09-24 · 대상 독자: X500 v2(코아 FC H743, PX4) + 라즈베리파이(pi3) 구성을 다루는 사람
출처는 문서 끝에 모았고, 본문에는 파라미터 이름을 그대로 적었다. QGC 파라미터 검색창에 넣으면 바로 나온다.

---

## 0. 전체 그림 — 누가 무엇을 정하는가

PX4는 층으로 나뉜다. 위층이 "어디로 갈지"를 정하고, 아래층이 "그러려면 모터를 얼마나 돌릴지"를 정한다.

```
[외부 입력]  RC 조종기        지상국(QGC)        컴패니언 컴퓨터(라즈베리파이)
                │                 │                      │
                └──────── MAVLink / uXRCE-DDS ────────────┘
                                  ↓
[모드 계층]   Commander(모드 전환·arm·failsafe 판정)  +  Navigator(미션·복귀·착륙)
                                  ↓  셋포인트(위치/속도/자세)
[제어 계층]   위치 제어 → 속도 제어 → 자세 제어 → 각속도 제어
                                  ↓
[출력]        믹서 → ESC → 모터
                                  ↑
[추정]        EKF2 ← IMU · 기압계 · 지자기 · GPS · (광류/비전)
```

세 가지만 기억하면 된다.

1. **외부에서 보내는 것은 "명령(command)"과 "셋포인트(setpoint) 스트림" 두 종류다.** 이륙·착륙·arm은 명령 한 번, 실시간 조종은 스트림.
2. **무엇을 받아 줄지는 지금 어떤 "모드"인지가 정한다.**
3. **모드 전환 권한은 Commander에게 있다.** 조건이 안 맞으면 거부하고, 위험하면 스스로 바꾼다(failsafe).

## 1. 드론을 제어하는 세 가지 경로

| 경로 | 무엇으로 | 실시간성 | 우리 구성에서 |
|---|---|---|---|
| RC 조종기 | 사람이 스틱으로 | 최상 | 항상 켜 둔다. 비상 개입 수단 |
| 미션(자율) | 미리 올린 웨이포인트를 Mission 모드로 실행 | 계획 실행 | 나중에 쓸 수 있음 |
| 외부 제어 | MAVLink / MAVSDK / ROS 2(uXRCE-DDS) | 링크 품질에 달림 | 라즈베리파이가 맡는 자리 |

### 1-1. 명령(command) — 한 번 보내고 결과를 받는 것

MAVLink `COMMAND_LONG`/`COMMAND_INT`으로 보내고 `COMMAND_ACK`로 수락·거절이 돌아온다.

| 하고 싶은 것 | MAVLink 명령 | MAVSDK |
|---|---|---|
| 시동/시동 해제 | `MAV_CMD_COMPONENT_ARM_DISARM` (400) | `action.arm()` / `action.disarm()` |
| 이륙 | `MAV_CMD_NAV_TAKEOFF` (22) | `action.takeoff()` |
| 착륙 | `MAV_CMD_NAV_LAND` (21) | `action.land()` |
| 복귀 | `MAV_CMD_NAV_RETURN_TO_LAUNCH` (20) | `action.return_to_launch()` |
| 모드 변경 | `MAV_CMD_DO_SET_MODE` (176) | 플러그인별 메서드 |
| 특정 메시지 주기 요청 | `MAV_CMD_SET_MESSAGE_INTERVAL` (511) | `telemetry.set_rate_*()` |

**수락은 "하겠다"는 뜻이지 "했다"는 뜻이 아니다.** 이륙 명령이 수락돼도 실제 고도 도달 여부는 텔레메트리로 따로 확인해야 한다.

### 1-2. 셋포인트 스트림 — 계속 보내야 유지되는 것

Offboard 모드에서 쓰는 방식이다. "지금 여기로" 또는 "이 속도로"를 **끊기지 않게 계속** 보낸다.

- MAVLink: `SET_POSITION_TARGET_LOCAL_NED`(위치·속도·가속도), `SET_POSITION_TARGET_GLOBAL_INT`(위경도), `SET_ATTITUDE_TARGET`(자세·각속도+추력)
- ROS 2: `OffboardControlMode`(생존 신호) + `TrajectorySetpoint` 등
- MAVSDK: `offboard.set_velocity_ned()` 같은 메서드. 내부적으로 20Hz로 자동 재전송해 준다

좌표계는 **NED**(북·동·아래)다. 고도를 올리려면 z가 **음수**다. 자세 쪽은 **FRD**(앞·오른쪽·아래) 기준.

## 2. 모드 변경

### 2-1. 모드를 바꾸는 주체

| 주체 | 방법 |
|---|---|
| 조종사 | RC 스위치 (QGC에서 채널에 모드를 배정) |
| 지상국·컴패니언 | `MAV_CMD_DO_SET_MODE`, 또는 이륙·착륙 명령처럼 모드 전환을 부수 효과로 일으키는 명령 |
| PX4 자신 | failsafe 발동, 또는 단계가 끝나 다음 모드로 넘어갈 때 |

### 2-2. 조건이 안 맞으면 거부한다

모드마다 요구 조건이 다르다. Commander가 조건을 보고 전환을 막는다.

| 모드 | 필요한 추정 |
|---|---|
| Stabilized, Acro | 자세만 |
| Altitude | 자세 + 고도 |
| Position, Offboard(위치 제어) | 지역 위치 추정 |
| Hold, Mission, Return | 전역 위치(GPS) |
| Takeoff, Land | 지역 위치 추정 |

**실내에서 GPS가 안 잡히면 Position·Hold·Mission·Return이 통째로 막힌다.** 실내 시험을 계획한다면 광류 센서나 모션캡처로 위치 추정을 만들어 줘야 한다.

### 2-3. 스틱을 건드리면 모드가 바뀐다

자동 모드(Takeoff, Land, Hold, Mission)에서는 **스틱을 조금만 움직여도 Position 모드로 넘어간다**(`COM_RC_OVERRIDE` 기본 켜짐, 민감도는 `COM_RC_STICK_OV`). 조종사가 즉시 개입할 수 있게 하는 장치다.

**Offboard 모드에서는 이 기능이 기본으로 꺼져 있다.** 라즈베리파이가 기체를 몰고 있을 때 스틱을 흔든다고 자동으로 회수되지 않는다. 회수하려면 **모드 스위치를 직접 돌려야** 한다. 시험 전에 조종사와 맞춰 둘 부분이다.

## 3. 기본 제어 과정에서의 모드 흐름

가장 흔한 "이륙 → 뭔가 하기 → 착륙"이 실제로 어떤 모드를 거치는지.

```
DISARMED
   │ arm 명령 (사전 검사 통과해야 수락)
   ▼
ARMED (기존 모드 유지)
   │ 이륙 명령
   ▼
AUTO.TAKEOFF ── 고도 도달 ──▶ AUTO.LOITER (Hold)   ← 아무 지시가 없으면 여기서 대기
   │ offboard 셋포인트를 1초 이상 2Hz로 보낸 뒤 모드 전환
   ▼
OFFBOARD ── 셋포인트 끊김(COM_OF_LOSS_T) ──▶ COM_OBL_RC_ACT가 정한 모드
   │ 착륙 명령
   ▼
AUTO.LAND ── 착지 감지 ──▶ 자동 DISARM (COM_DISARM_LAND, 기본 2초)
```

단계별로 알아 둘 것.

**arm**
- 사전 검사를 통과해야 한다. 센서 캘리브레이션, home 위치 설정, 자세 추정 정상, (모드에 따라) GPS 품질. MAVSDK에서는 `telemetry.health_all_ok()`로 미리 볼 수 있다.
- 안전 스위치가 달려 있으면 그걸 먼저 눌러야 한다(`COM_PREARM_MODE`).
- arm 후 `COM_DISARM_PRFLT`(기본 10초) 안에 이륙하지 않으면 자동으로 시동이 꺼진다. **arm만 해 놓고 다른 일을 하면 저절로 disarm된다.**

**이륙**
- 고도는 `MIS_TAKEOFF_ALT`(기본 2.5m), 상승 속도는 `MPC_TKO_SPEED`(기본 1.5m/s).
- 도달하면 **스스로 Hold로 넘어가 대기한다.** 다음 지시를 안 보내도 떨어지지 않는다.

**Offboard 진입**
- 진입 **전에** 셋포인트를 보내고 있어야 한다. PX4는 신호를 1초 넘게 받은 뒤에야 offboard를 허용한다.
- 진입 후에도 2Hz 아래로 떨어지면 나간다.
- 제자리에 머무르려면 "현재 위치"를 계속 보내야 한다. 보내기를 멈추는 건 정지가 아니라 **링크 끊김**이다.

**착륙**
- 착지 후 `COM_DISARM_LAND`(기본 2초) 뒤 자동 disarm.

**이륙·착륙은 offboard로 하지 말 것.** PX4 문서가 명시한다. offboard가 받는 명령 종류는 제한적이고, 이륙·착륙·복귀는 전용 모드가 훨씬 안전하게 처리한다. 셋포인트로 고도를 올려 이륙시키는 식은 피한다.

## 4. PX4가 제공하는 기능

### 4-1. 비행 모드 (멀티콥터)

| 구분 | 모드 | 내용 |
|---|---|---|
| 수동 | Position | 스틱을 놓으면 제동하고 위치를 유지. 가장 안전한 수동 모드 |
| 수동 | Position Slow | 속도·회전을 제한한 Position. 장애물 근처나 규정상 필요할 때 |
| 수동 | Altitude | 고도만 유지. 수평으로는 관성과 바람에 흐름. GPS 불필요 |
| 수동 | Stabilized | 수평만 잡아 줌. 지상국에서 "Manual"을 고르면 이 모드 |
| 수동 | Acro | 곡예용. 자세를 잡아 주지 않음 |
| 자동 | Hold | 현재 위치·고도에서 정지 호버링. 임무 일시정지와 비상 회수에 씀 |
| 자동 | Takeoff / Land | 수직 이륙 후 Hold / 그 자리 착륙 |
| 자동 | Return | 안전 고도로 올라가 home이나 랠리 지점으로 복귀 후 착륙 |
| 자동 | Mission | 미리 올린 비행 계획 실행 |
| 자동 | Orbit / Follow Me | 한 점을 중심으로 선회 / 비콘 추종 |
| 자동 | Offboard | 외부(컴패니언·지상국)가 주는 셋포인트를 따름 |

### 4-2. 안전 장치

| 장치 | 파라미터 | 동작 |
|---|---|---|
| RC 신호 상실 | `COM_RC_LOSS_T`, `COM_FAIL_ACT_T`, `NAV_RCL_ACT` | 대기 후 Hold/Return/Land/Disarm 등 |
| 데이터링크 상실 | `COM_DL_LOSS_T`, `NAV_DLL_ACT` | 지상국 링크가 끊기면 Hold/Return/Land 등 |
| Offboard 상실 | `COM_OF_LOSS_T`, `COM_OBL_RC_ACT` | 셋포인트가 끊기면 Position/Altitude/Manual/Return/Land 중 설정값으로 |
| 배터리 | `COM_LOW_BAT_ACT` | 경고 → 복귀 → 즉시 착륙, 단계별 |
| 지오펜스 | `GF_ACTION`, `GF_MAX_HOR_DIST`, `GF_MAX_VER_DIST` | 경계를 넘으면 경고/Hold/Return/Land/종료 |
| 킬 스위치 | `COM_KILL_DISARM` | 모터 출력 즉시 중단. **날고 있으면 떨어진다** |
| 고장 감지기 | Failure Detector | 이륙 중 이상 자세 등을 감지해 모터 정지 |

RC 신호 상실 failsafe는 offboard 중에 성가실 수 있다. `COM_RCL_EXCEPT`의 bit 2를 세우면 offboard 모드에서만 RC 상실을 무시한다. **조종기를 아예 쓰지 않겠다는 뜻이므로 실내·실외 어디서든 신중히 판단할 것.**

### 4-3. 그 밖에

- 파라미터 시스템(약 1,700개 중 우리 기체는 960개 사용), QGC에서 조회·변경
- 비행 로그(.ulg) 기록과 Flight Review 분석
- MAVLink 인스턴스별 설정: 포트(`MAV_x_CONFIG`), 모드(`MAV_x_MODE`), 전송량(`MAV_x_RATE`)
- 시뮬레이션(SITL, Gazebo). `make px4_sitl gz_x500`으로 X500 모델 그대로 사용 가능
- 미션 업로드·다운로드는 모드와 무관하게 언제든 가능

## 5. 라즈베리파이와 연결할 때 반드시 볼 것

### 5-1. 링크 설정

- **`MAV_x_MODE`를 Onboard로.** 컴패니언용 메시지 조합과 주기가 적용된다. 우리 구성은 TELEM2 = `MAV_1`(`/dev/ttyS3`), 921600, Onboard. TELEM1 = `MAV_0`, 57600, Air Unit.
- **보드레이트는 양쪽이 같아야 한다.** `SER_TEL2_BAUD`와 라즈베리파이 쪽 설정.
- **포트를 여러 프로그램이 나눠 쓰려면 mavlink-router.** PX4 공식 문서도 컴패니언 구성에서 이 방식을 권한다. 우리는 TCP 5760(QGC), UDP 14540(제어 코드), 14541·14542(감시), 14543(브리지)로 갈라 뒀다.
- **시리얼 포트를 두 프로그램이 동시에 열면 안 된다.** 라우터가 물고 있을 때는 다른 도구는 UDP로 붙는다.

### 5-2. Offboard를 쓸 때

| 규칙 | 내용 |
|---|---|
| 2Hz | 셋포인트가 2Hz 아래로 떨어지면 모드에서 나간다. 여유 있게 10~20Hz 권장 |
| 1초 선행 | 모드 전환 **전에** 최소 1초 이상 보내고 있어야 진입이 허용된다 |
| 위치 추정 | 위치 셋포인트를 쓰려면 지역 위치 추정이 있어야 한다. 실내 GPS 없음 = 사실상 불가 |
| RC | offboard 중 RC는 모드 변경 외에는 먹지 않는다. 스틱 오버라이드도 기본 꺼짐 |
| 이륙·착륙 | offboard로 하지 말고 Takeoff/Land 모드를 쓴다 |
| 실패 대비 | `COM_OF_LOSS_T`와 `COM_OBL_RC_ACT`를 먼저 설정하고 시험한다 |

### 5-3. 우리 구조에서 특히 걸리는 것

**① 데이터링크 상실 failsafe를 먼저 확인하라.** 라즈베리파이 인스턴스가 Onboard로 잡혀 있어도, 지상국 링크(Air Unit) 쪽이 끊기면 `NAV_DLL_ACT`가 발동할 수 있다. 실외 시험 전에 `COM_DL_LOSS_T`와 `NAV_DLL_ACT`를 확인하고, 의도한 동작인지 판단해 둘 것.

**② 라즈베리파이는 FC의 안전망이 아니다.** 제어 주기가 1~2ms인 층은 FC 안에 있고, 리눅스는 그 주기를 보장하지 못한다. 라즈베리파이가 멈춰도 FC가 기체를 붙잡는 구조를 유지해야 한다. 지금처럼 브리지를 읽기 전용으로 두고, 제어는 별도 프로그램이 명시적으로 할 때만 나가게 하는 방식이 여기에 맞는다.

**③ 전원.** FC와 라즈베리파이가 같은 배터리를 쓴다. 비행 중 모터 부하로 전압이 내려가면 BEC 출력도 흔들린다. 비행 전에 모터를 돌린 상태에서 `vcgencmd get_throttled`가 `0x0`인지 확인한다.

**④ 시간.** 라즈베리파이에 RTC가 없어 부팅 직후 시각이 틀어져 있을 수 있다. 로그를 FC와 맞춰 볼 생각이면 NTP나 FC의 `SYSTEM_TIME`으로 기준을 맞춘다.

**⑤ 실기 전에 SITL.** `make px4_sitl gz_x500`으로 같은 코드를 먼저 돌린다. offboard 진입 조건, failsafe 동작, 모드 전이를 기체 없이 그대로 확인할 수 있다.

**⑥ 조종기는 항상 켜 둔다.** offboard 중 회수는 모드 스위치로 한다. 스틱을 흔드는 것으로는 안 된다.

### 5-4. 우리 기체 현재 값 (2026-09-21 확인)

| 파라미터 | 값 |
|---|---|
| `MAV_0_CONFIG` / `MAV_0_MODE` / `SER_TEL1_BAUD` | 101(TELEM1) / 0(Normal) / 57600 — Air Unit |
| `MAV_1_CONFIG` / `MAV_1_MODE` / `SER_TEL2_BAUD` | 102(TELEM2) / 2(Onboard) / 921600 — 라즈베리파이 |
| `UXRCE_DDS_CFG` | 0 (미사용) |
| 기체 | MAV_TYPE_QUADROTOR, sysid 1 |

아직 설정하지 않은 것: `COM_OF_LOSS_T`, `COM_OBL_RC_ACT`, 지오펜스(`GF_*`), 킬 스위치 채널. **제어 명령 시험 전에 이 넷을 정해야 한다.**

- [Flight Modes (Multicopter)](https://docs.px4.io/main/en/flight_modes_mc/) — 모드 목록과 수동·자동 구분, 전환 조건
- [Offboard Mode](https://docs.px4.io/main/en/flight_modes/offboard.html) — 2Hz 규칙, 1초 선행, 지원 메시지, `COM_OF_LOSS_T`·`COM_OBL_RC_ACT`·`COM_RCL_EXCEPT`
- [Takeoff Mode (MC)](https://docs.px4.io/main/en/flight_modes_mc/takeoff.html) — `MIS_TAKEOFF_ALT`, `MPC_TKO_SPEED`, 완료 후 Hold 전이
- [Land Mode (MC)](https://docs.px4.io/main/en/flight_modes_mc/land.html) — `MPC_LAND_SPEED`, `COM_DISARM_LAND`, `MAV_CMD_NAV_LAND`
- [Hold Mode (MC)](https://docs.px4.io/main/en/flight_modes_mc/hold.html) — 전역 위치 요구 조건
- [Arming and Disarming](https://docs.px4.io/main/en/advanced_config/prearm_arm_disarm.html) — 사전 검사, 안전 스위치, `COM_DISARM_PRFLT`
- [Safety Configuration](https://docs.px4.io/main/en/config/safety.html) — RC/데이터링크/배터리/지오펜스 failsafe, 킬 스위치
- [Companion Computers](https://docs.px4.io/main/en/companion_computer/) — FC와 컴패니언의 역할 분담, mavlink-router 권장
- [Raspberry Pi Companion with Pixhawk](https://docs.px4.io/main/en/companion_computer/pixhawk_rpi.html) — 배선과 파라미터
- [MAVLink Messaging](https://docs.px4.io/main/en/middleware/mavlink.html) — 스트림과 `MAV_CMD_SET_MESSAGE_INTERVAL`
- [ROS 2 User Guide](https://docs.px4.io/main/en/ros2/user_guide.html) — uXRCE-DDS 경로와 좌표계 규약

MAVSDK 문서

- [Taking Off and Landing](https://mavsdk.mavlink.io/main/en/cpp/guide/taking_off_landing.html) — 명령 수락과 완료의 구분, health 확인 후 arm
- [Offboard Control](https://mavsdk.mavlink.io/main/en/cpp/guide/offboard.html) — 셋포인트 선행 지정, 20Hz 자동 재전송

MAVLink 표준

- [Common message set](https://mavlink.io/en/messages/common.html) — `MAV_CMD_COMPONENT_ARM_DISARM`, `MAV_CMD_NAV_TAKEOFF`, `MAV_CMD_NAV_LAND`, `SET_POSITION_TARGET_LOCAL_NED` 등

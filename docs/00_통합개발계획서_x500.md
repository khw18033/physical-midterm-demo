## 2. 무엇을 만드는가

### 2-1. 한 문단

현재 코드는 비행 모드를 **바꾸지도 읽지도 않는다.** 바꾸지 않는 것은 의도된 설계이므로 유지한다.
**읽지 않는 것이 문제다.** 모드를 읽어서 ① 로그에 남기고 ② **사람이 개입하면 코드가 물러나게** 한다.

> **모드 조회가 필요한 이유는 명령을 더 보내기 위해서가 아니라,
> 언제 명령을 멈춰야 하는지 알기 위해서다.**

### 2-2. 왜 — 고치려는 문제 셋

**① 사람이 개입해도 코드가 모르고 `land()` 를 보낸다** ← 가장 위험

`takeoff_land.py` 는 `finally` 로 **무조건** `land()` 를 보내는데 모드를 보지 않는다.

| t | 사람 | 코드 | 기체 모드 |
|---|---|---|---|
| 0s | — | `takeoff()` | `AUTO.TAKEOFF` |
| 3s | **이상 감지 → 개입** | (모름) | `POSCTL` — 사람이 조종 중 |
| 8s | 수동 조종 중 | **`land()` 발사** | **`AUTO.LAND` 로 다시 뺏김** |

**사람과 코드가 기체를 두고 싸운다.**

**② 모드 해석기가 실행 스크립트 안에 있다**
`decode_px4_custom_mode()` 가 `check_link.py` 에 있고 공용 헬퍼 `dronelink.py` 에는 없다.
저장소 밖 MQTT 브리지가 `check_link.py` 를 라이브러리처럼 import 한다.

**③ 모드 이름이 두 벌이다**
pymavlink 경로는 `AUTO.LOITER`, MAVSDK 경로는 `HOLD`. 같은 상태를 다른 단어로 부른다.
지금은 사람 눈으로만 보니 넘어가지만 **코드가 모드로 분기하면 바로 버그가 된다.**

### 2-3. 만들지 않는 것 (범위 밖)

| 안 만든다 | 이유 |
|---|---|
| **OFFBOARD** | 파이가 죽으면 즉시 페일세이프. 현재 설계의 근본 전제를 깬다 |
| **웹에서 조종** | MQTT 규약이 `ping` 하나. 브리지는 `DevicePolicy=closed` 로 시리얼을 못 연다 |
| **자율 경로 비행·미션 업로드** | 이번 범위 아님 |
| **실내 비행** | GPS 기반 위치 추정을 요구한다. 광류/외부측위 + 코드 수정이 따로 필요 |
| **FC 파라미터 쓰기** | 사람이 QGC 로만. 자동화가 설정을 바꾸면 원인 추적 불가 |

```

   ├── drone-detect    (root, 부팅 필수, 라우터를 띄우는 주체)
```

> 그리고 이 파일이 끝나기 전에 다른 코드를 건드리지 않는다.

### P1. `dronelink.py` 승격 — 유일한 위험 구간

> ⚠ **전 과정 프로펠러 제거 상태. arm 상태에서는 어떤 서비스도 재시작하지 않는다.**

#### P1-1. `dronelink.py` 에 모드 어휘 추가 — **순수 추가만**

```python

                 5:"RTL", 6:"LAND", 7:"RTGS", 8:"FOLLOW_TARGET", 9:"PRECLAND"}

def decode_px4_custom_mode(custom_mode):      # check_link 에서 그대로 이동
    main = (custom_mode >> 16) & 0xFF
    sub  = (custom_mode >> 24) & 0xFF
    ...

MAVSDK_TO_PX4 = {                              # ★ 어휘 통일 (문제 ③)
    "TAKEOFF": "AUTO.TAKEOFF", "HOLD": "AUTO.LOITER",
    "LAND": "AUTO.LAND", "RETURN_TO_LAUNCH": "AUTO.RTL",
    "MISSION": "AUTO.MISSION", "READY": "AUTO.READY",
    "POSCTL": "POSCTL", "ALTCTL": "ALTCTL", "MANUAL": "MANUAL",
    "STABILIZED": "STABILIZED", "OFFBOARD": "OFFBOARD", "ACRO": "ACRO",
}
def normalize_mode(mavsdk_flight_mode) -> str: ...
```

### P4. 제어 경로 모드 연동 — `takeoff_land.py`

#### P4-1. 모드 감시 태스크

```python
shared = {"mode": None, "prev": None}

async def watch_mode(drone, shared):
    async for m in drone.telemetry.flight_mode():
        name = normalize_mode(m)
        if name != shared["mode"]:
            print(f"[모드] {shared['mode']} → {name}")
            shared["prev"], shared["mode"] = shared["mode"], name
```

#### P4-2. 시간 대기 → 상태 대기

```python
EXPECTED = {"AUTO.TAKEOFF", "AUTO.LOITER", "AUTO.LAND"}

await drone.action.takeoff()
await wait_mode(shared, "AUTO.TAKEOFF", timeout=5)    # ← 10 아님. 아래 참고
await wait_mode(shared, "AUTO.LOITER",  timeout=30)   # 고도 도달
print(f"[대기] 호버 안정 — 여기서부터 {args.hold}초")
await hold_or_abort(shared, args.hold)
```

> **근거** — PX4 공식 문서: *"수락은 '하겠다'는 뜻이지 '했다'는 뜻이 아니다."*
>
> **★ 타임아웃을 10초로 잡으면 안 된다.** `COM_DISARM_PRFLT` 기본값이 **10초**다 —
> arm 후 그 안에 이륙하지 않으면 PX4 가 스스로 disarm 한다. 10초로 두면
> **"명령이 씹혔다" 와 "PX4 가 시동을 껐다" 를 구분할 수 없다.**
> **P0-4 에서 읽은 실측값보다 확실히 짧게 잡는다.**
>
> 현재 코드의 `set_takeoff_altitude()` → `arm()` → `takeoff()` 순서는
> 파라미터 쓰기가 arm 앞이라 이 10초를 잡아먹지 않는다. **이 순서는 유지한다.**

#### P4-3. ★ 사람이 뺏으면 손을 뗀다 — 문제 ① 의 해법

```python
async def hold_or_abort(shared, seconds):
    deadline = time.monotonic() + seconds
    while time.monotonic() < deadline:
        if shared["mode"] not in EXPECTED:
            raise ModeTakenOver(shared["mode"])   # land() 를 보내지 않는다
        await asyncio.sleep(0.1)
```

`finally` 의 무조건 `land()` 를 교체:

```python
except ModeTakenOver as e:
    print(f"[중단] 모드가 {e.mode} 로 바뀌었다 — 사람 또는 FC 가 기체를 잡았다.")
    print("       스크립트는 land 를 보내지 않는다. ★ 조종기로 마무리할 것 ★")
    if e.mode == "POSCTL":
        print("       (POSCTL = 스틱 오버라이드. 일부러 개입했거나 스틱이 살짝 건드려졌다.")
        print("        어느 쪽이든 기체는 지금 조종기 것이다. 그대로 착륙시킨다.)")
    return 2
```

| 바뀐 모드 | 해석 | 행동 |
|---|---|---|
| **`POSCTL`** | 사람이 뺏음 — 모드 스위치 **또는 스틱 오버라이드** | 즉시 손 뗌 |
| `ALTCTL` / `MANUAL` / `STABILIZED` | 사람이 모드 스위치로 뺏음 | 즉시 손 뗌 |
| `AUTO.RTL` | **FC 페일세이프 발동** | 손 뗌 + 로그 |
| `AUTO.LAND` (내가 안 보냈는데) | FC 페일세이프 | 손 뗌 + 로그 |
| `AUTO.TAKEOFF` → `AUTO.LOITER` | 정상 | 계속 |

> **`POSCTL` 이 특별한 이유**: `COM_RC_OVERRIDE` 가 **기본 켜짐**이라 자동 모드에서
> **스틱을 조금만 움직여도** Position 으로 넘어간다. 우리는 AUTO 만 쓰므로 이게 살아 있다.
> 개입 수단이 둘 다 작동하는 건 좋지만, **실수로 건드려도 똑같이 abort 된다.**
> 판정은 바꾸지 않는다 — 어느 쪽이든 기체는 이미 조종기 것이다.
>
> **`AUTO.RTL` 도 실제로 일어날 수 있다**: `NAV_DLL_ACT` 는 라즈베리파이 링크뿐 아니라
> **Air Unit(지상국) 링크가 끊겨도** 발동할 수 있다. 그때 `land()` 를 보내면
> 귀환 중인 기체를 그 자리에 내려 버린다.

# places/ — 장소 계약의 세 층 중 둘

Unity 맵에서 뽑는 것을 **셋으로 가른다.** 한 파일에 섞으면 생성기가 좌표를 보게 되고,
그 순간 모델이 503호 전용이 된다.

| 층 | 내용 | 파일 | 쓰는 곳 |
|---|---|---|---|
| **위상** | 장소 · 별칭 · 종류 · 층 · 인접 | `places.json` | `VZ-G-01`·`VZ-G-02` 그라운딩, `VZ-G-03` 검증 |
| 기하 | 좌표 · 거리 | `places.geometry.json` | `VZ-G-04` 전개 · 시연 · 임무 `params` |
| 렌더 | 메시 · 머티리얼 | 뽑지 않는다 | Unity 만 |

이 분리가 논문 4-6 「범용성 장치」의 다섯째다 — *계층마다 필요한 데이터가 다르고,
그것이 파일로 갈라져 있다.*

`verify:places` 의 4번 검사가 `src/generate/` 와 `gen-lab/server/` 를 훑어
**기하 파일을 읽는 경로가 없는지** 본다.

## 지금 상태 — 채워져 있다

장소 **54건** (방 20 · 문 26 · 복도 2 · 지물 5 · **자리표시 1**), 인접 76변.
`npm run extract:places` 로 다시 뽑는다. 손으로 고치지 마라 — 원천은 씬이다.

## 좌표 기준 — `site-global` 은 Unity 가상환경 좌표다

**`N45F_Map.unity` 의 월드 좌표계가 `site-global` 이다. 단위는 m.**
이 정의가 이 저장소의 기준이고, 다른 좌표가 들어오면 이쪽으로 변환한다.

| 원천 | 상태 |
|---|---|
| `N45F_Map.unity` 월드 | **기준.** 복도 · 문 26 · 엘리베이터 · 계단 · 화장실 |
| `XRI/lab.unity` 월드 (503호 실내) | **변환해서 합쳤다.** 앵커는 문 하나(`Door` ↔ `door-503`), 회전 없음, 오프셋 (−40.46, −55.26) |
| 대본 `scenarios/*.json` 의 `frame: "site-global"` | **이름만 같고 다른 세계다.** 아래 |

### 대본의 `frame` 이름이 잘못 붙어 있다 — 미결

`MSN-260831-01` 의 `elevator_position` 은 `(51.6, 0, −4.2)` 이고 `frame: "site-global"`
이라고 적혀 있다. 그런데 기준 좌표계의 엘리베이터는 `(−7.36, 8.11, −45.29)` 다.

대본의 `worldTimeline` 을 보면 로봇이 `(9.0, −6.5)` 에서 `(48.9, −4.2)` 까지 **x 축에
평행한 직선**으로 간다. 방향 변화가 3.3° 뿐이다. 기준 좌표계에서 같은 임무는 방에서
`+z` 로 7.7 m 나온 뒤 복도에서 `+x` 로 30.5 m 가는 **83° 꺾인 경로**다.
평행이동으로도 겹쳐지지 않는다.

거리는 맞춰 두었다 — 대본 총 이동 40.34 m, 기준 좌표계 38.24 m, 차이 5%.
**손으로 만들 때 거리 감각은 잡았고 좌표계만 임의로 잡은 것이다.**

지금은 아무것도 깨지지 않는다. `elevator_position` 을 읽는 코드가 0이고
`drive.position` 은 `scenarios/axes.ts` 가 키의 존재만 본다. **`VZ-G-04` 전개가
좌표를 숫자로 쓰는 순간 걸린다.**

**대본은 고치지 않는다** — 4편은 HCI 전달본이자 §2 정답셋이고, 좌표 때문에 건드리면
채점 기준이 같이 흔들린다. `VZ-G-04` 는 이 표를 보고 대본의 `frame` 값을 믿지 않으면 된다.

## 자리표시 — 아직 재지 않은 곳

**지금 잰 것은 5층 복도와 503호뿐이다. 4층 맵 데이터는 없다**(2026-09-07 확인).

`room-415` 는 옛 편 `MSN-260826-01` 의 발화(「415호에서 503호로」)에 나오므로
**자리는 두되 인접을 비운다.** 4층 복도·엘리베이터를 이어 붙이면 재지 않은 위상을
지어내는 것이고, 그 지도로 낸 숫자는 실측 위에 서 있지 않게 된다.

`verify:places` 가 셋을 본다 — 자리표시에 **좌표가 없는가** · **인접이 없는가** ·
`held_open` 목록이 실제 장소를 가리키는가.

### 그래서 415→503 임무는 지금 평가할 수 없다

모델에게 415호는 **어디로도 이어지지 않은 섬**이다. 층 이동 경로를 낼 근거가
프롬프트 안에 없다. 그 편의 점수를 다른 편과 같은 표에 올리면 **우리 지도의 구멍이
모델의 점수로 찍힌다.**

4층을 재면 그때 잇는다. 그 전까지는 **없는 것을 없는 대로 둔다.**

## 좌표의 출처와 정밀도

| | |
|---|---|
| 방법 | **줄자 실측** + N4동 지상5층 피난 안내도 사진을 Unity 밑그림으로 깔고 트레이싱 |
| 안내도 | `Unity_Map/Assets/N4_5F_Corrider/Images/N4_5F.jpg` (2026-01-09 촬영). 머티리얼 `N4_5F.mat` 로 감싸 밑그림으로 쓰고 지금은 어느 씬도 참조하지 않는다 |
| 정밀도 | **측량 등급이 아니다.** 줄자 실측이라 오차가 있고, 안내도에는 축척 표시가 없다 |
| 높이(y) | **실측이 아니다.** z 축을 고려하지 않고 둔 편의값이다 — 기하 파일에 y 를 넣지 않은 이유다 |

논문·보고서에서 이 데이터를 말할 때는 **「줄자 실측 기반」**까지가 정확하다.
「측량」이나 「도면 기반」이라고 쓰면 근거를 넘어선다.

## 채울 때 지켜야 하는 것

- **`shared/registry.ts` 와 같은 규칙이다.** 장소 목록을 아는 면은 하나여야 한다.
- **대본에 나오는 장소가 전부 들어 있어야 한다.** 4편의 발화·마일스톤 제목에 등장하는
  장소를 뽑아 대조하는 것이 `verify:places` 다.
- **없는 층·구역을 지어내지 마라.** 잰 것은 503호와 5층 복도다.
  4층 자리표시 셋은 아래 규칙을 따른다.
- **방은 번호로만 부른다.** 기능 이름(강의실 · 산학협동실)은 안내도에는 있지만 씬에는
  없는 정보이고 방 용도는 바뀐다. 그때마다 추출 결과가 흔들리면 그것은 실측이 아니다.
- **문은 노드다** (지시서 0-2). 대본 1편의 `MS-B` 가 「문 열림 확인」이므로 문이
  마일스톤을 만들어내는 대상이다. 엣지 속성으로 두면 `VZ-G-01` 이 그 마일스톤을 낼
  근거가 사라진다.
